# Инвентаризация: что в программе не используется

Оснастка, которой сделан раунд чистки refactor4 (отчёт —
`docs/zametti-refactor4-report.md`). Отвечает на вопрос «кто это зовёт» и его
следствие «а если не зовёт никто» — СЕМАНТИЧЕСКИ, через clangd, а не текстовым
поиском: правило проекта прямое (CLAUDE.md, «Железные запреты»), и в каждом
прошлом отчёте была ошибка, выросшая из grep.

## Как этим пользоваться

```
cd <корень репозитория>
cmake -S . -B build                    # база компиляции свежая
ZAMETTI_INVENTORY_DIR=/tmp/zametti-inv \
    python3 scripts/inventory/inventory.py            # все три прохода
ZAMETTI_INVENTORY_DIR=/tmp/zametti-inv \
    python3 scripts/inventory/inventory.py closure    # только замыкание
```

Первый запуск строит свой индекс (наши ~215 TU, без `3rdparty`) — около двух
минут на `-j4`; дальше индекс переиспользуется. Результаты ложатся рядом с
индексом: `closure.json`, `macros.json`, `locals.json`.

**После добавления или удаления файлов и после правки CMake базу надо
перегенерировать, а индекс — снести** (`rm -rf <работа>/cdb/.cache`), иначе
clangd отвечает по устаревшей картине.

## Три прохода

- **closure** — замыкание живого. Узлы: все функции, методы, типы и константы в
  `.h` И `.cpp` ядра. Ребро A→B: внутри определения A есть ссылка на B. Корни:
  ссылки из `app/`. Живое = достижимое из корней; остальное — DEAD,
  а если его зовут только наборы — TEST-ONLY.

  Считается именно ЗАМЫКАНИЕ, а не список «у кого ноль ссылок»: снятие крупного
  куска открывает следующий слой. `illustrate` мёртв, а `gapLabel` жив ровно до
  тех пор, пока жив `illustrate`.

- **macros** — поля настроек (`ZM_SETTING*` в `settings.h`, `app_state.h`). У
  сгенерированных `name()/setName()/nameMin()/nameMax()` нет токена в исходнике,
  поэтому текстовые совпадения берутся ИЗБЫТОЧНЫМ фильтром, и каждое
  подтверждается `goToDefinition` — ведёт ли оно в объявляющий заголовок.

- **locals** — функции и методы во всех наших `.cpp` (включая `app/`,
  `tests/`) с числом ссылок: так находятся мёртвые местные помощники.

## Чему верить и чему нет

- **«Ноль ссылок» — доказательство только при проверенной полноте индекса.**
  Скрипт ждёт конца фоновой индексации и лишь потом задаёт вопросы; перед
  большим прогоном полезно проверить известную ссылку (например, что
  `resampleLanczos` виден из `tests/resample_test.cpp`).
- **clangd систематически недосчитывает три вещи**: строковые `SIGNAL()/SLOT()`,
  символы, рождённые макросами, и переопределения виртуальных методов (ссылка
  может идти на базовый). Прежде чем удалять такое — смотреть глазами.
- Найденное делится на четыре судьбы, и они разные: удалить; перенести проверки
  на преемника и удалить; спрятать в `.cpp` (публичное, но внутреннее);
  оставить как названный тестовый люк или судью инвариантов.

## Ещё один инструмент рядом

`xwd2png.py` — снимок экрана Xvfb (`xwd -root`) в PNG без чужих библиотек.
Печатает разбор заголовка (`1600x1000, 32 бит/пиксель, строка 6400 байт`):
дважды за историю проекта этот конвертер писали с перепутанным полем и
принимали полосатую кашу за артефакт вёрстки.

Ловушка при снимках: если в среде есть `WAYLAND_DISPLAY`, Qt уходит в wayland
мимо заданного `DISPLAY`, и на снимке пусто. Запускать так:

```
DISPLAY=:77 QT_QPA_PLATFORM=xcb WAYLAND_DISPLAY= ./build/app/zametti --root <хранилище>
```
