# Zametti — бриф для Claude Code, этап 2: редактирование

## Контекст

Этап 1 закрыт: ядро `zametti-core` (markdown → IR → markdown, оба инварианта
идемпотентности, md4c вендорингом) и просмотрщик с деревом заметок. Документы:
`zametti-brief-m1.md`, `zametti-core-notes.md`, `zametti-m1-report.md` — прочитать
все три перед началом, там зафиксированы решения, которые здесь не повторяются.

Этап 2 превращает просмотрщик в редактор. Критерий всего этапа один:
**данные не теряются никогда, undo доступен всегда**.

Дорожная карта после этого этапа (id вместо имён файлов, импорт из Apple Notes,
шифрование, синхронизация, macOS) влияет на текущую работу ровно одним способом:
ничего из неё не реализовывать и не закладывать «на вырост».

## Цель этапа

1. WYSIWYG-редактирование открытой заметки с сохранением в тот же файл.
2. Обратный путь `QTextDocument → IR` (`document_reader`) с проверяемым инвариантом.
3. Undo/redo, который не пропадает — в том числе при изменении файла снаружи.
4. Сохранение, после которого файл гарантированно читается обратно в тот же документ.

## Не-цели

Не реализовывать, не проектировать «на вырост», не оставлять заглушек:

- переход на id-имена файлов, конвертация корпуса, импорт из Apple Notes;
- шифрование, синхронизация, история ревизий на диске;
- поиск и индекс;
- Android, QML;
- подсветка синтаксиса в блоках кода;
- таблицы, сноски и прочее из `rawSource` как моделируемые сущности;
- новые возможности просмотрщика (панели, вкладки, экспорт).

Не-цели — это не пожелания. Если кажется, что без чего-то из списка не обойтись, —
остановиться и спросить.

## Первая задача этапа: механизм маркеров

До написания какого-либо кода ввода — зафиксировать, как сейчас нарисованы
буллеты и чекбоксы (штатный `setMarker` отвергнут ещё на этапе 1).

Правило, к которому надо привести реализацию: **маркер — это отрисовка, а не
содержимое документа**. Если текущий вариант — `QTextObjectInterface` или иной
объект, занимающий позицию в тексте (`U+FFFC`), то маркер физически является
символом, и это даст три класса проблем в редакторе: копирование утащит
object-replacement-символ в буфер обмена, `Home`/стрелки обязаны перепрыгивать
маркер, а все смещения спанов сдвинутся на единицу в каждом блоке.

В этом случае — оценить переход на отрисовку по геометрии блока (кастомный
paint поверх вьюпорта или наследник лэйаута) и согласовать решение **до**
реализации операций. Если маркеры уже рисуются вне текста — зафиксировать это
в отчёте и двигаться дальше.

## Архитектура

```
zametti-core/            # в этом этапе НЕ меняется
app/
  document_builder.cpp   # IR → QTextDocument (есть)
  document_reader.cpp    # QTextDocument → IR (новое)
  editor_ops.cpp         # операции редактирования — функции над QTextDocument
  editor_widget.cpp      # виджет: трансляция ввода в вызовы операций
  main.cpp
tests/
  reader_test            # инварианты builder/reader
  ops_test               # операции: given IR → build → op → read → expected IR
  undo_test              # op + undo == identity
  external_change_test
```

Жёсткие правила разделения:

- **Логика редактирования живёт в `editor_ops` — функциях над `QTextDocument`.**
  `keyPressEvent` и обработчики мыши только транслируют ввод в вызовы операций.
  Ни одного изменения документа напрямую из обработчика события.
- Ядро в этом этапе не трогается. Если операция требует правки IR или
  сериализатора — остановиться и спросить.
- Тесты гоняются без дисплея (`QT_QPA_PLATFORM=offscreen`); для `QTextDocument`
  достаточно QtGui, QtWidgets в тестовых бинарниках быть не должно.

## Модель документа

- Источник истины для рода блока — свойства `UserProperty` в `QTextBlockFormat`:
  `kind`, `level`, `headingLevel`, `info`. Область значений маленькая и конечная —
  `QTextFormatCollection` интернирует форматы, и уникальные значения на блок
  (id, timestamp) класть в форматы **запрещено**: это убивает дедупликацию.
- Объекты `QTextList` — производный артефакт отрисовки. Их пересобирает
  `syncLists`; никакой другой код их не создаёт и не чинит.
- `rawSource`-блоки в редакторе — литеральный текст: курсор входит, текст
  правится как есть (моноширинное отображение остаётся), при чтении обратно
  отредактированный текст становится новым `rawSource` и выводится дословно.
  Никакого повторного разбора содержимого при правке.

## Операции

Каждая операция — отдельная функция с сигнатурой над документом и диапазоном
блоков, обёрнутая в `beginEditBlock()`/`endEditBlock()` (одна операция = один шаг
undo), с тестом. Список закрытый; расширять по согласованию.

**`syncLists(from, to)`** — нормализующий проход: максимальный непрерывный прогон
блоков с одинаковым ключом `(level, isOrdered(kind))` делит ровно один `QTextList`
(`Bullet`/`TaskUnchecked`/`TaskChecked` — одно семейство). Инвариант после любой
операции, в debug-сборке — ассертом:

- соседние блоки с равным ключом принадлежат одному списку;
- скачков уровня больше чем на 1 относительно предыдущего блока нет;
- первый блок списка имеет уровень 1.

**indent / outdent** (`Tab` / `Shift+Tab` в списке):

- отступ разрешён, только если предыдущий блок имеет уровень ≥ текущего;
  первый элемент списка не отступается — операция молча не делает ничего;
- если у выделенного пункта есть вложенные дети, не покрытые выделением, —
  они двигаются вместе с ним (диапазон расширяется до поддерева);
- после операции выделение восстанавливается по номерам блоков, не по позициям.

**Enter**:

- в пункте списка — новый пункт того же рода и уровня (для task — `Unchecked`);
- на **пустом** пункте — снять список (пункт становится абзацем), не создавая
  нового; повторный Enter не нужен;
- в середине текста пункта — разрезание текста, остаток уходит в новый пункт.

**Backspace в начале пункта** — пункт становится абзацем (уровень и род
снимаются); текст не сливается с предыдущим блоком. Обычный Backspace внутри
текста — штатный.

**Перемещение пункта** (`Ctrl+Up` / `Ctrl+Down`; хоткей — параметр конфига):
пункт списка под курсором меняется местами с соседним пунктом **того же
уровня** — предыдущим или следующим. Единица перемещения — пункт вместе со
своим поддеревом: все последующие блоки с уровнем больше его собственного едут
вместе с ним; поддерево соседа при обмене — тоже. У первого пункта `Alt+Up`
молча не делает ничего, у последнего — `Alt+Down`; сосед ищется в пределах
непрерывной списочной области, через абзац операция не перепрыгивает. Для
блоков вне списков операция в этом этапе — no-op.

Курсор остаётся на том же смещении внутри перемещённого пункта, вьюпорт следует
за ним (`ensureCursorVisible`). Перенумерация после обмена происходит сама;
`syncLists` на затронутый диапазон обязателен.

Реализация — через уже существующую пару reader/builder: оба диапазона (пункт с
поддеревом и сосед с поддеревом) читаются в IR-фрагменты, меняются местами и
вставляются обратно одним edit block. Это надёжнее жонглирования курсором и
гарантированно сохраняет свойства блоков.

**Клик по чекбоксу** — переключение `TaskUnchecked ↔ TaskChecked`. Хит-тест по
той же геометрии, по которой маркер рисуется (одна функция геометрии на
отрисовку и на хит-тест, не две копии).

**Конвертация типов** на диапазон: команды «сделать bullet / ordered / task /
paragraph». Семантика — «установить», не «переключить»: при смешанном выделении
все блоки приводятся к запрошенному роду. Правила из этапа 1:

- task → ordered: чекбокс деградирует в литеральный текст `[x] ` / `[ ] ` в
  начале содержимого (правило «молча не терять»);
- текст `[x]` при конвертации в bullet обратно в чекбокс **не** продвигается —
  промоушен только при парсинге файла и при явном вводе;
- paragraph: род и уровень снимаются, текст не меняется.

**Инлайн-форматирование**: bold / italic / strike на выделение (`Ctrl+B` - bold,
`Ctrl+I` - italic, `Ctrl+/` striKethrough). Без выделения —
переключение формата в точке ввода для последующего набора. Внутри
`Span::code`-прогонов и `rawSource`-блоков инлайн-команды не действуют.

**Input rules** при наборе в начале блока: `- ` → bullet, `1. ` → ordered,
`[ ] ` в начале пункта-буллета → task, `#{1..6} ` → заголовок. Автозамена —
отдельный шаг undo: первый `Ctrl+Z` возвращает набранные символы, а не
предыдущую правку.

## Буфер обмена

Обменный формат — сам markdown. Отдельный внутренний MIME-тип не нужен: у нас
уже есть парсер и сериализатор, и их идемпотентность гарантирует, что
скопированное внутри приложения вставится без потерь. Это осознанное решение,
не упрощение.

- `createMimeDataFromSelection` / `insertFromMimeData` / `canInsertFromMimeData`
  **переопределяются обязательно**. Иначе Qt кладёт в буфер собственный HTML и
  вставляет чужой HTML напрямую в документ, минуя модель.
- **Копирование**: выделение → IR-фрагмент → `serialize` → `text/plain`.
  Частично выделенные первый и последний блоки входят во фрагмент с обрезанным
  текстом и пересчитанными спанами, род и уровень сохраняются. Списочные уровни
  фрагмента ребейзятся так, чтобы минимальный стал 1. Следствия, которые
  являются тестами: вставка в любой внешний редактор даёт валидный markdown;
  копирование всего документа побайтово равно сериализации.
- **Вырезание** = копирование + удаление диапазона. Правило склейки для
  диапазона, начинающегося и кончающегося в середине блоков: хвост последнего
  блока приклеивается к голове первого, объединённый блок наследует род и
  уровень первого. После склейки — `syncLists` и починка скачков уровня на шве
  (лишние уровни опускаются до допустимых); ассерты инварианта обязательны.
  Это же правило действует для любого межблочного удаления (Delete/Backspace
  через границу блока), не только для Ctrl+X.
- **Вставка**: `text/plain` разбирается **полным парсером ядра** в IR-фрагмент —
  никакого второго упрощённого разбора. Дальше по форме фрагмента:
  - одиночный абзац без структуры — инлайновая вставка в текущий блок, спаны
    переносятся со сдвигом;
  - иначе — блочная: текущий блок при необходимости режется по курсору, фрагмент
    входит блоками с уровнями как есть (база 1), `syncLists` сшивает с
    окружением;
  - `Ctrl+Shift+V` — вставка литерального текста в текущий блок без разбора.
- `rawSource`-блоки копируются дословным текстом; повторный разбор при вставке
  даёт тот же `rawSource` — это следствие второго инварианта ядра, отдельного
  кода не требует, но тест обязателен.
- Каждая операция буфера — один edit block; undo возвращает документ целиком.

## Undo

- `QTextDocument` ведёт стек сам; задача этапа — не сломать его:
  каждая операция один edit block, свойства блоков и маркерные объекты обязаны
  корректно переживать undo/redo (это проверяется `undo_test`, см. ниже).
- **Сохранение не сбрасывает и не сегментирует undo-стек.**
- IME/композиция: промежуточные состояния композиции не должны попадать в стек
  отдельными шагами. Проверить руками с русской раскладкой и любым IME.

## Внешние изменения файла

Претензия, ради которой всё затевалось: редактор, молча перечитавший файл и
потерявший undo, — это провал. Правила:

- следить за файлом (`QFileSystemWatcher` + проверка хеша содержимого, mtime —
  только подсказка);
- если документ **не** имеет несохранённых правок — применить внешнее содержимое
  как обычную редакционную операцию (один edit block, diff старого и нового IR →
  минимальная замена диапазона блоков; в вырожденном случае — полная замена).
  Undo после этого возвращает прежнее состояние — внешняя правка стала просто
  ещё одним шагом истории;
- если несохранённые правки **есть** — ничего не затирать молча: неблокирующее
  уведомление с выбором «взять внешнее (как undoable-операцию) / оставить моё
  (внешняя версия будет перезаписана при сохранении)». Никакого третьего
  «умного» поведения в этом этапе.

## Сохранение

- Путь: `QTextDocument → document_reader → IR → serialize`.
- Автосохранение с дебаунсом (параметр в конфиге), плюс сохранение при потере
  фокуса окна, при закрытии и по `Ctrl+S`.
- Не писать, если сериализованное содержимое не изменилось (сравнение хешей) —
  чтобы не дёргать mtime и не плодить ложные события у будущей синхронизации.
- Атомарность: запись во временный файл в том же каталоге + `rename`.
- **Самопроверка перед rename**: сериализованный текст разбирается обратно, и
  полученный IR сравнивается с IR документа. Совпало — rename; не совпало —
  старый файл не трогается, буфер сохраняется в аварийный файл рядом
  (`имя.md.rescue-<timestamp>`), пользователю показывается ошибка. Это последний
  рубеж против потери данных, и он не отключается.

## Инварианты и тесты

Главные инварианты этапа:

```
A. read(build(ir)) == ir                        для IR из парсера, по всем корпусам
B. открыть файл и сохранить без правок == serialize(parse(file))
   (для уже канонических файлов — побайтовая идентичность)
C. op + undo == identity                        на уровне IR, для каждой операции
```

Обязательные тесты:

- `reader_test`: инвариант A по корпусам этапа 1 (`.testdata/…`), включая
  golden-файлы с кириллицей — пересчёт смещений UTF-8 ↔ UTF-16 в обе стороны;
- `ops_test`: для каждой операции таблица случаев `IR до → IR после`, включая
  все правила из раздела «Операции» (запрет скачков уровня, поддерево детей при
  indent, Enter на пустом пункте, деградация чекбокса при task → ordered);
- `undo_test`: инвариант C — каждая операция на корпусных документах, затем
  undo, сравнение IR побайтово через сериализацию; отдельно undo после input rule;
- фаззинг операций: случайные последовательности операций со случайными
  диапазонами на корпусных документах; после каждой — ассерты `syncLists`;
  в конце — `serialize → parse → read == документ`;
- `clipboard_test`: копирование выделения с границами в середине блоков и
  разными уровнями на концах → golden-markdown; вырезание через уровни →
  склейка и инварианты; «вставка текста X в пустой документ» эквивалентна
  «открыть файл X»; копировать → вырезать → вставить на то же место == identity
  на уровне IR; копирование всего документа == сериализация;
- `move_test`: перестановка с поддеревом у обоих участников, no-op на границах
  и вне списка, перенумерация ordered, курсор в перемещённом пункте,
  move + undo == identity;
- `external_change_test`: оба сценария (без правок / с правками), в первом —
  undo возвращает состояние до внешнего изменения;
- тест самопроверки сохранения: искусственно испорченный reader → старый файл
  цел, rescue-файл создан.

## Правила работы

- **Ничего за пределами репозитория не трогать.** Тесты и ручные проверки живут
  в `XDG_CONFIG_HOME` внутри каталога сборки; `rm` по путям вне сборки запрещён;
  `~/Documents/vpnotes` и корпуса в `.testdata/` — только чтение.
- Секция «Мои ошибки» в отчёте обязательна.
- Измерять, а не рассуждать; простое решение предпочтительнее общего.
- Сомнение — повод спросить, а не додумать.
