# Отчёт 18a: книги — метаданные, модель, ввоз fb2, замок, карточка (05.09.2026)

Бриф: `docs/brief-18.md`. План: `~/.claude/plans/swirling-exploring-torvalds.md` (в репозиторий не
входит; решения владельца сверх брифа перечислены ниже). Ветка `books`, восемь коммитов от
`35baf21` (бриф) до `69a9e70` (карточка).

## Решения владельца, принятые в сессии (поверх брифа)

1. Документ один — `ZNote`/`ZDocument`; режим чтения (18b) — отдельный `ZBookView` на том же живом
   документе редактора.
2. Пометки — в тексте: `==пометка=={>>комментарий<<}`. Букмарки — **в отдельном файле
   `bookmarks.json`**, не в шапке (18b).
3. Замок книги — **мягкий, ключ `lock: yes`**; `access: read-only` остаётся жёстким, как был.
4. History на тулбаре у `role: book` гасится; журнал ведётся как у всех.
5. Интерлиньяж и прочее запечённое — по роли документа при сборке; смена режима чтения не
   пересобирает документ (18b).
6. Кнопка ввоза одна — «Import text», берёт `.md` и `.fb2`.
7. Уточнения после ревью плана (значок комментария на правом поле, букмарк слева бордовым,
   пункт меню Hide/Show marks, `←`/`→`, ленивый пересчёт страниц, поиск в чтении) — все 18b.
8. Хвостовой `\r` у строки сноски в заметке «Typesetting Math in Markdown» нормализуется каноном;
   копия заметки в `tests/testdata` (и `.testdata`) пересохранена отдельным коммитом.

## Сделано

### §1 Шапка и метаданные (`4f00136`)

- `NoteHeader`: `lock: yes` (`locked()/setLocked()`, незнакомое значение не запирает и
  говорит в stderr — как у `access`), `safeValue()` для значений извне (`--` → `- -`, переводы
  строк → пробел, края обрезаны).
- `ZNote`: `isBook()`, `isLocked()/setLocked()`, `bookAuthor()`, `bookYear()`; `Metadata` несёт
  `book`, `locked`, `author`, `year` — индекс хранилища знает карточку книги без чтения файла.
- `docs/info/zametti-storage.md`: строки таблицы ключей — `lock`, `role: book`, `author`,
  `translator`, `year`, `isbn`, `publisher`, `series`, `lang`, `genre`, `cover`, `source`.

### §2 Модель markdown (`3b0697c`, `b0b4008`)

- `InlineFlag` и `Run::flags` — 16 бит (восемь были заняты). Новые спаны: `InlineSup`/`InlineSub`
  (`<sup>`/`<sub>`, через `QTextCharFormat::setVerticalAlignment`), `InlineFootnote` (`[^id]`,
  в документе — id надстрочным цветом ссылки, в файле — как написано). Новый род блока
  `Kind::Footnote` (`[^id]: текст`, id в `InfoProperty`, строки продолжения с отступом в четыре
  пробела; метка id рисуется на левом поле `paintMarker`, кегль — новая настройка
  `fonts.footnoteStep`, по умолчанию −1).
- **Сноски — мимо md4c.** Пробник подтвердил: `[^1]: Ibid.` md4c съедает как link reference
  definition, а `[^1]` в тексте делает ссылкой с href «Ibid.». Пре-проход `maskFootnotes`
  маскирует определения (`[` → буква) и ссылки (`[^id]` → апострофы: буква после `_` делала
  подчёркивание внутрисловным и ломала курсив) в копии, которую читает md4c; текст всегда
  берётся из исходника. Определение узнаётся по метке U+E000, которую пре-проход ставит вместо
  НЕэкранированной `[` в начале строки, — не по виду текста: `\[^2]: …` из заметки владельца
  определением не является. `[^1](url)` — ссылка с текстом «^1» (тоже из заметки владельца) —
  не маскируется; `[^1][^2]` — две ссылки.
- Писатель: `<sup>`/`<sub>` — атрибуты внутри ссылки, снаружи кода; сноска — дословно; блок
  `[^id]: …`; текст вида `[^id]` экранируется (`\[^id]`), иначе читался бы ссылкой.
  `wouldMerge`: определение сноски — абзац для md4c, между двумя стоит пустая строка.
- Найдено и починено по дороге: `withRunsAsPartition` в саверe держал флаги в `uint8_t` и
  молча терял девятый бит (первый же `<sup>` пропадал при записи).
- Golden: `tests/golden/footnotes.md|json`, `sup_sub.md|json`; корпус, roundtrip, FileCanon —
  зелёные.
- **Отклонение от плана:** жёсткий перенос (`\`+новая строка) НЕ заведён. Мягкие переносы `\n`
  внутри абзаца уже сохраняются файлом и рисуются переводом строки, стихам этого достаточно;
  `MD_TEXT_BR` по-прежнему уводит абзац в дословный кусок.

### §3 Ввоз fb2 (`6a3b998`, `570b378`)

- `zametti-core/import/fb2_book.{h,cpp}` — `Fb2Book`: `QXmlStreamReader` без обработки
  пространств имён (файлы без привязанного префикса иначе отвергались бы), имена и атрибуты по
  локальной части. Выдаёт **блоки `Piece`, а не markdown**: текст пишет единственный писатель
  (`writePieces`), и канон — его. Таблица §2 брифа воплощена с уточнениями по корпусу:
  эпиграф/цитата/поэма — одна плоская цитата (вложенных цитат в модели нет), строфа — абзац
  цитаты со строками-переносами, висячий отступ строки стиха сохраняется обычными пробелами;
  секция без заголовка → `___`; заголовок из нескольких `<p>` → « · »; `text-author` → «— Автор»;
  таблица → GFM дословным блоком; аннотация — первой цитатой после заголовка, экранированный
  HTML в ней снимается (Паустовский); все `body` с именем — определения сносок, сироты тоже;
  id сносок вне `[A-Za-z0-9_-]` → `n1…` с отображением; `[^1](url)`-подобные ссылки
  не трогаются. Кодировка: `windows-1251` — таблицей 128 записей (ICU в отгружаемом Qt
  выключен), декларация переписывается; utf-8/utf-16 — Qt; прочее — честная ошибка со строкой.
- `ZStorage::importBook(parentId, path, limits, error, report)`: картинки из `<binary>` — через
  штатный конвейер `importImage` (временный файл в зоне temp; jpeg → jxl байт-точным транскодом,
  большие — путём фото), имена вложений — `createAttachmentFile`; блоки → `writePieces` → `ZNote`
  → шапка (`role: book`, `lock: yes`, поля §1, `cover`, `source: <имя> blake3:<hex>`, `created`
  из `document-info/date`) → общий с `importNote` хвост `finishImport` (времена, канонический
  круг, `createNoteFile`, `refreshNote`). `verify` и уборка вложений при удалении знают про
  `cover:` (первое — правкой, второе — по построению: поиск идёт по байтам файла).
- `note_id.h`: `createAttachmentFile` — единый O_EXCL-цикл для заметок и вложений;
  `createNoteFile` и `writeFresh` редактора идут через него.
- CLI: `zametti store import-book <file.fb2> --root <dir> [--parent <id>]`, печатает времена и
  числа. Окно: кнопка «Import text», фильтр `*.md *.markdown *.fb2`, диспетчер по расширению.
- Тесты: `tests/fb2_import_test.cpp` — публичный рукописный `tests/testdata/fb2/sample.fb2`
  (все элементы таблицы) и его cp1251-близнец, golden `sample.md` (id вложений и `modified`
  вне сравнения), карточка книги в дереве; приватный корпус `.testdata/books` — ввоз всех 11,
  инвариант «каждый `a[type=note]` → ровно одна ссылка с определением», картинки не теряются,
  `verify` без бед.

### §4 Мягкий замок (`93ee465`)

- `NoteEditor`: `isLockedNote()`, `isTemporarilyUnlocked()`, `setTemporaryUnlock()`,
  `setNoteLocked()` (через `editMeta` — запись сразу, `modified` не трогается),
  `isEffectivelyLocked() = archived || accessReadOnly || (locked && !temp)`, сигнал
  `lockChanged`. Временное разрешение — по id в памяти, снимается в `stashCurrentNote`.
- **Найдено по дороге:** собственный `keyPressEvent` редактора не смотрел на `isReadOnly()` —
  набор проходил в запертый документ (архив и read-only жили в `ReaderView`, и дыру никто не
  трогал). Теперь всё, что правит, отсекается после undo/redo; отмена оставлена нарочно —
  пометки книги должны отменяться.
- Тулбар: кнопка `Lock` перед History (значок `lock`/`lock-open`, временное — акцентом);
  открыто → запереть без вопроса; временно открыто → запереть обратно; заперто → окно с тремя
  ответами через `ZApp::messageBox`. `ToolbarState`: `lockedNote`, `tempUnlocked`, `book`;
  History у книги погашена с причиной; Lock погашен на документации, архиве, `access: read-only`.
- Пять иконок Lucide (`lock`, `lock-open`, `book-open-text`, `bookmark`, `message-square-more`)
  из `lucide-static` 1.41.0, ISC; README иконок дополнен.
- Тесты: `tests/lock_test.cpp` (набор не проходит, курсорная правка проходит, temp сбрасывается
  при переключении, снять/поставить пишет шапку без `modified`, перенос запертой разрешён,
  read-only по-прежнему отказывает); `toolbar_state_test` расширен (маска 128 состояний).

### §5 Карточка книги (`69a9e70`)

Вместо новых ролей и ветки делегата — строка «Автор · год» кладётся в слот сниппета при сборке
узла дерева (`note_tree.cpp`), книга в дереве получает значок `book-open-text`. Виду и модели
списка менять ничего не пришлось. Проверено в `fb2_import_test` через `NoteTreeModel::rowOf`.

## Пробники

- **cp1251 в Qt без ICU**: не запускал `QStringDecoder` на portable-сборке — таблица нужна по
  факту конфигурации (`packaging/*/qtbase-configure.sh`, `build-qt.sh`: `-no-icu`), и она
  сделана безусловной.
- **md4c и `[^1]: слово`**: `mddump` — определение съедено, ссылка стала href «Ibid.». Пре-проход
  обязателен.
- **Два вида на одном `QTextDocument`** (scratchpad `shared-doc`, Qt 6.11, offscreen,
  40 000 блоков): `setDocument` во второй `QTextEdit` не отбирает документ у первого; стек отмены
  переживает переключение; переключение страниц стека — 12 мс в первый раз, 1 мс дальше;
  **ширина у документа одна**: после возврата к редактору `textWidth` остался читалкиным (480 при
  вьюпорте 880) — активный вид обязан переустанавливать свою ширину (`applyContentWidth`) при
  каждом показе. Это фундамент `ZBookView` в 18b.

## Отклонения от брифа и реализованные `[VETO?]`

- Аннотация книги — цитатой первым блоком (`[VETO?]` принят).
- Обложка не вставляется в тело, только `cover:` в шапке (`[VETO?]` принят).
- Секция без заголовка → `___` (`[VETO?]` принят); заголовок из нескольких `<p>` → « · »
  (`[VETO?]` принят); все именованные `body` → сноски (`[VETO?]` принят).
- Карточка книги «автор · год» (`[VETO?]` принят, реализован через слот сниппета).
- Жёсткий перенос не заведён (см. §2) — мягкие переносы уже делают то, что нужно стихам.
- Сноска «сирота» (определение без ссылки) пишется — по брифу.
- Замок кладётся в файл `editMeta`, а не через `ZStorage`: ни перечитывания, ни потери отмены.

## Мои ошибки

- **Придумал битые PNG для образца** (сочинил base64 «на глаз») и сначала счёл отказ конвейера
  ошибкой конвейера. Настоящий PNG сгенерирован кодом; правило «измерять, а не рассуждать»
  относится и к тестовым данным.
- **Пробел перед стилем прилипал к стилю** (`с* курсивом*`): нормализация пробелов в `Para`
  ставила отложенный пробел уже внутри размеченного куска. Поймано первым же ввозом образца, а не
  наборами модели — образец с реальной разметкой обязателен раньше, чем тесты «на бумаге».
- **Маска ссылок буквами** ломала курсив (`_it_xxxx_al_` — внутрисловное подчёркивание).
  Найдено набором InlineFormula на заметке владельца; маска стала апострофами.
- **Определение сноски искал по виду текста**, и `\[^2]:` с экранированной скобкой становилось
  сноской. Исправлено меткой U+E000 из пре-прохода — признак должен идти от исходника, а не
  восстанавливаться по тексту.
- **`[^1](url)` — ссылка с текстом «^1»** (заметка владельца) — маскировалась как сноска; потом,
  исключив `[` и `(` после метки, я заодно сломал `[^1][^2]`. Теперь `[` после метки исключает
  только настоящую reference-ссылку.
- **Не проверил, что `keyPressEvent` редактора чтит `isReadOnly()`**, пока набор замка не показал
  «abc» в запертой книге. Архив и read-only жили в другом виджете, и дыра была невидима.
- **Первый набор для карточки** написал с закрытым `attachmentPath` и указателем `info()` —
  API надо читать, а не угадывать.

## Долги

- `FuzzOps.All` красный, как до ветки (см. отчёт 05.09.2026 §5: два файла корпуса Apple Notes);
  моих провалов там нет.
- Локальные ссылки `#id` в книгах остаются текстом (не-цель брифа).
- Сноски: перенос строки в определении — только продолжением с отступом; пустой строки внутри
  определения канон не держит (второй абзац после пустой строки станет обычным абзацем).
- `<sup>` без пары уводит абзац в дословный кусок (по правилу «непонятое — дословно»).
- Импорт `import-book` не пишет запись журнала сам — как и `importNote`, опорная запись ляжет при
  первом открытии заметки.
- Позиция «Import text» в диалоге: один фильтр на оба формата; `.fb2.zip` — не-цель.
- Ввоз Роджерса (519 картинок) — 4.3 с в GUI-потоке; ввоз книги идёт синхронно, как ввоз `.md`.
  Фоновый ввоз — если владелец сочтёт нужным.
- Пробник cp1251 на portable-сборке не гонял (таблица безусловна).
