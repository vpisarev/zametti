# Zametti — бриф для Claude Code, этап 1

## Контекст

Zametti — персональный заметочник на markdown (Linux + macOS сейчас, Android позже).
Файлы на диске — обычный markdown, правятся любыми внешними инструментами и лежат в git.
Приложение не владеет форматом, а лишь читает и пишет его.

Этап 1 закрывает **ядро формата** и минимальный просмотрщик. Всё остальное — позже.

## Цель этапа

1. Библиотека `zametti-core`: `markdown → IR → markdown` с побайтовой идемпотентностью.
2. Просмотрщик: один `.md` на входе, окно с отрендеренным документом.
3. Флаг `--check`: прогнать `parse → serialize`, вывести дифф с оригиналом, вернуть ненулевой код при расхождении.

Просмотрщик здесь — не самоцель, а первый стенд для проверки ядра.

## Явные не-цели

Не реализовывать, не проектировать «на вырост», не оставлять заглушек:

- редактирование (ввод, курсор, undo, Tab/Shift-Tab, конвертация списков);
- дерево заметок, навигация, боковая панель;
- поиск и индекс;
- синхронизация, git, шифрование, история ревизий;
- Android, QML;
- картинки, сноски, reference-ссылки, HTML-блоки как *моделируемые* сущности (см. `rawSource`).

Если по ходу кажется, что без чего-то из списка не обойтись, — остановиться и спросить.

## Архитектура

```
zametti-core/            # НЕ зависит от QtWidgets
  ir.h                   # структуры IR
  parser.cpp             # md4c → IR
  serializer.cpp         # IR → markdown
  json_dump.cpp          # IR → JSON, односторонне, только для тестов и отладки
app/
  document_builder.cpp   # IR → QTextDocument
  main.cpp               # окно + режим --check
tests/
  roundtrip_test.cpp
  golden/                # пары .md / .json
```

Жёсткое требование: **в `zametti-core` не должно быть ни одного include из QtWidgets**.
Проверяется механически — тестовый бинарник линкуется только с ядром, без QtWidgets.
Зависимость от QtCore допустима, но лучше обойтись стандартной библиотекой.

Ядро работает в **UTF-8** (`std::string`). Конверсия в UTF-16 происходит ровно в одном
месте — в `document_builder.cpp` при вставке текста в `QTextDocument`.

## IR

Транзиентное представление: живёт только на время загрузки и сохранения, рядом с
`QTextDocument` никогда не существует. Синхронизировать его ни с чем не нужно и нельзя.

```cpp
enum class Kind {
    Paragraph,
    Heading,          // headingLevel = 1..6
    Code,
    Bullet,           // level = вложенность
    TaskUnchecked,    // level = вложенность
    TaskChecked,      // level = вложенность
    Ordered,          // level = вложенность
};

inline bool isList(Kind k) { return k >= Kind::Bullet; }

struct Span {
    int  offset;        // в байтах, от начала Block::text
    int  length;
    bool bold   = false;
    bool italic = false;
    bool strike = false;
    std::string href;   // непусто → ссылка
};

struct Block {
    Kind kind         = Kind::Paragraph;
    int  headingLevel = 0;                   // осмысленно только при Kind::Heading
    int  level        = 0;                   // осмысленно только при isList(kind)
    std::string text;                        // чистый текст, без маркеров
    std::vector<Span> inlines;
    std::string rawSource;                   // непусто → выводить дословно, остальные поля игнорировать
};

using Document = std::vector<Block>;
```

Модель **плоская**. Дерева нет: вложенность списков выражается целым `level`,
сериализатор восстанавливает отступы из уровней.

## Правила, которые надо закодировать

Это принятые решения, а не предложения к обсуждению.

1. **Род блока — один enum, а не набор параллельных флагов.** Блок не бывает
   одновременно заголовком и элементом списка, кодом и заголовком, нумерованным
   пунктом и чекбоксом. Все эти состояния взаимно исключающи, поэтому кодируются
   значениями `Kind`, а не отдельными полями. Критерий: нелегальное состояние
   должно быть непредставимо, а не отлавливаться валидатором.

   Зависимые параметры (`headingLevel`, `level`) осмысленны только при
   соответствующих значениях `Kind`; в остальных случаях они равны нулю и не
   читаются. Проверять это ассертом на входе сериализатора.

   Следствие для группировки списков: `Bullet`, `TaskUnchecked` и `TaskChecked`
   принадлежат одному семейству и должны попадать в один прогон, `Ordered` — в
   другой. Ключ прогона — не само значение `Kind`, а его проекция:
   `(level, isOrdered(kind))`.

2. **`[x]` после маркера нумерованного списка — это литеральный текст, а не чекбокс.**
   `Ordered` и `TaskChecked` — разные значения одного enum, то есть комбинация
   непредставима by construction. Расширение tasklists в md4c отключать нельзя
   (на нём держатся обычные `- [ ]`), поэтому при `is_task` внутри `MD_BLOCK_OL`
   маркер надо вернуть в текст самому.

   Определяется по стеку охватывающих блоков: `MD_BLOCK_LI` с `is_task` приходит
   внутри `MD_BLOCK_OL` или `MD_BLOCK_UL`; правило срабатывает только для первого.

   Брать **срез исходного буфера**, а не синтезировать строку `"[x] "` — иначе
   потеряется `X` в верхнем регистре и лишние пробелы, и побайтовое равенство
   сломается. Границы среза:

   - начало: `task_mark_offset - 1` (это `[`; сам `task_mark_offset` указывает на
     символ между скобками);
   - конец: от `task_mark_offset + 2` промотать вперёд только пробелы и табы.

   Конец среза **нельзя** определять по смещению первого текстового колбэка: на входе
   `1. [x] **жирный** текст` первым придёт `MD_SPAN_STRONG`, у которого смещения нет
   вовсе, а первый текст — уже `жирный`. Срез до него проглотит `**`, которые
   сериализатор потом выведет ещё раз из спана. Идти надо по буферу.

3. **Непредставимое сохраняется дословно** в `rawSource`: таблицы, сноски,
   reference-ссылки, HTML-блоки, картинки. Молча терять нельзя ничего.

4. **Канонический вывод.** Всегда `-` для маркированных списков. Нумерация всегда с 1
   (`start` не поддерживается). Чередования disc/circle/square нет. Отступ — 2 пробела
   на уровень.

5. **Канон инлайновой вложенности:** strong снаружи, emphasis внутри (`**_x_**`).
   Подчёркивания нет ни в модели, ни в выводе.

6. **Широкий вход, узкий выход.** Парсер принимает всё, что принимает CommonMark
   (`*`, `+`, `-`; `1.` и `1)`; отступы 2/3/4 пробела; setext-заголовки), и приводит к канону.
   Пишет всегда одинаково.

## Критерий приёмки

Главный инвариант, вокруг которого строятся тесты:

```
serialize(parse(x)) == x               побайтово, для x в каноническом виде
parse(serialize(parse(x))) == parse(x) для произвольного x
```

Обязательные тест-кейсы:

- списки с чередующимися уровнями `1 → 3 → 2`;
- два разнотипных списка подряд без пустой строки между ними;
- `1. [x] текст` — остаётся текстом;
- `- [X] текст` и `- [ ]  текст` (двойной пробел) — побайтовый возврат;
- fenced code с пустыми строками и с markdown-подобным содержимым внутри;
- setext-заголовки на входе → ATX на выходе (канон), и это **не** должно ломать
  второй инвариант;
- список, прерванный абзацем, и список внутри цитаты;
- таблица и HTML-блок → `rawSource`, побайтовый возврат;
- пустой файл, файл без завершающего перевода строки, CRLF.

Плюс фаззинг: прогнать оба инварианта по корпусу реальных заметок (путь к дереву
передаётся параметром) и по мутациям из него.

Golden-тесты: `.md` рядом с ожидаемым JSON-дампом IR. `from_json` **не писать** —
дамп односторонний, иначе он незаметно станет вторым форматом хранения.

## Открытый вопрос по парсеру

md4c — SAX-парсер, и границ блоков в исходнике он напрямую не отдаёт. Для `rawSource`
предлагаемый подход: в текстовых колбэках считать смещения через арифметику указателей
(`text - buffer`), накапливать min/max по блоку и расширять диапазон до границ строк —
таблицы и HTML-блоки занимают целые строки, поэтому этого должно хватать.

**Это гипотеза, а не проверенный рецепт.** Проверить на реальных примерах в первую
очередь; если не работает — остановиться и предложить альтернативу, не изобретая
обходных путей молча.

## Просмотрщик

`QTextBrowser` (не `QTextEdit`): read-only из коробки, `setOpenExternalLinks(true)`.

Сборка документа:

- `doc.setUndoRedoEnabled(false)` на время построения;
- всё внутри `cursor.beginEditBlock()` / `endEditBlock()`;
- **флаг `first`**: свежий `QTextDocument` уже содержит один пустой блок — для первого
  блока использовать `setBlockFormat`, а не `insertBlock`, иначе сверху появится пустой абзац;
- списки: держать текущий прогон, ключ — `(level, isOrdered(kind))`, то есть
  `Bullet`/`TaskUnchecked`/`TaskChecked` не разрывают прогон; при смене ключа
  `cursor.createList()`, иначе `list->add(cursor.block())`. Два соседних `QTextList`
  с одинаковым ключом — баг (даст нумерацию `1. 2. 1. 2.`);
- чекбоксы: `QTextBlockFormat::setMarker(...)` для `TaskUnchecked`/`TaskChecked`;
- смещения `Span` — в байтах UTF-8, при вставке конвертировать инкрементально,
  идя по спанам по порядку. Наивное приравнивание байтовых смещений к индексам
  `QString` — ошибка, которая проявится только на не-ASCII.

Оформление (иначе всё слипнется в комок):

- `doc.setDocumentMargin(24)`, явные `setTopMargin`/`setBottomMargin` у блоков —
  межабзацного интервала в Qt по умолчанию нет;
- заголовки: `setHeadingLevel(n)` + `setFontPointSize(base * {1.7, 1.45, 1.25, 1.1})`;
- код: `setFontFamilies({"monospace"})`;
- блоки `rawSource`: моноширинный серый текст — должно быть видно, что это непонятая
  конструкция.

## Технические рамки

- C++20, CMake.
- md4c через FetchContent или вендорингом; флаги: GitHub-диалект с tasklists,
  strikethrough, tables.
- Новых зависимостей не добавлять без согласования.
- Тесты обязательны для ядра; для просмотрщика достаточно ручной проверки.

## Стиль работы

- Измерять, а не рассуждать: любое утверждение о производительности подкрепляется замером.
- Простое решение предпочтительнее общего. Инкрементальный парсинг, кэши и
  оптимизации на этом этапе не нужны — md4c разбирает сотню килобайт за доли миллисекунды.
- Сомнение — повод спросить, а не додумать.
