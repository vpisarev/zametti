## 2. Форма, которая уже согласована с владельцем

Облако принадлежит хранилищу; операции синка адрес в параметрах НЕ носят.

```cpp
bool setRemote(const std::shared_ptr<RemoteStore>&, const Keyfile&, QString*);
bool pushAll(PushReport*, QString*);                 // есть
// сессия 4:
bool useLastRemote(SecretStore&, QString*);          // ждёт бухгалтерии
void markDirty(const QString& id);                   // зовут пути записи
QStringList takeDirty();
struct SyncOptions { enum Mode { Full, PushOnly } mode = Full;
                     int deleteGuard = 20; int exitPushBudgetSec = 10; };
bool sync(const SyncOptions&, SyncReport*, QString*);
```

`sync()` наследует форму `pushAll` — внутри порядок шагов инвариант:
`выравнивание → обмен → объединение → материализация`.

## 3. Что делать в сессии 4 (порядок — от независимого к зависимому)

1. **`ZJournal::mergedWith(const ZJournal&)`** — чистая функция от двух
   наборов записей, БЕЗ ЕДИНОГО ФАЙЛА в проверках (ради этого журнал и
   отделён от диска). Union по ключу «время + отпечаток»; порядок и голова —
   существующий `Record::isBefore` (`max(seq, time, контент-старше-надгробия,
   отпечаток)`), второй формулы заводить нельзя. Property-тесты:
   `union(A,B) ⊇ A и ⊇ B`, `merge(A,B) ≡ merge(B,A)` побайтово при равных
   наборах. Гашение применяется по адресам — механика (`voids`, `isVoided`,
   `indexesOf`) уже есть и уже используется чисткой.
2. **Property «вычищенное не возвращается»** — долг, названный в отчёте 3:
   журнал, вычищенный гашением, слитый с досодержавшей его копией, не
   воскрешает погашенное.
3. **Бухгалтерия `sync-state`** — КЭШ, НЕ ИСТИНА (инвариант D: её удаление
   не меняет результата синка). Живёт в каталоге приложения, файл по
   (storeId + хеш локального пути) — две копии на машине не делят её.
   На блоб: etag последней операции, BLAKE3 залитого шифротекста, BLAKE3
   локального журнала на тот момент. Она же закрывает «повторный push-all
   заливает всё заново» и даёт `useLastRemote`.
4. **Выравнивание O(изменений)**: dirty-set с write-ahead пометкой ДО
   записи. Место для хука названо в долгах refactor5 (§7): `writeFileBytes`,
   а не только `ZNote::save` — иначе байтовые правки шапки (архив, бюро
   находок, resurrect) пройдут мимо. Плюс stat-скан на десктопе.
5. **Обмен — три яруса** (бриф, шаг 2), включая валидацию целостности
   ДО классификации: не прошёл — трактуем как absence, ноль заливок.
6. **Материализация** через существующий external-путь (undoable-правка,
   Ctrl+Z возвращает своё) + предохранитель массового удаления с семантикой
   отказа «эти заметки объявлены живыми».
7. **`zametti-store sync --full|--push-only`** — тот же глагол; `push-all`
   в нём растворяется.

## 4. Грабли, на которые я наступил — не наступайте снова

- **Проверка обязана краснеть при снятой починке, и снимать надо целиком.**
  Три проверки из этой сессии были пустышками и нашлись только снятием
  (§8 отчёта 3). Если снятие не покраснело — вероятнее, что неверно снятие,
  а не что проверка хороша: у меня так было дважды.
- **Кодировки называть явно.** Qt кодирует basic auth не в UTF-8 (пароль с
  кириллицей → 401 на каждой операции); `QLatin1String` от байтов UTF-8 даёт
  двойное кодирование. Оба случая нашлись только пробником против живого
  сервера.
- **`printf` вычисляет аргументы в неопределённом порядке** — `printf("%d
  %s", ok(&err), qPrintable(err))` печатает ошибку ДО вызова.
- **Мерить тем, что различает измеряемое**: миллисекунды округлили в ноль
  сумму сотен шифрований.
- **Forward-объявление внутри `namespace zametti`** объявляет СВОЙ тип.
- **Ничего вне репозитория.** Команда, поднимающая чужой демон, — это запись
  в чужой каталог, даже если в ней нет ни одного пути (я так завёл связку в
  `~/.local/share/keyrings`).
- **`configure_file` заменяет незаданную переменную ПУСТОЙ строкой**, а не
  оставляет `@ИМЯ@`.

## 5. Числа, от которых можно отталкиваться

Первый полный синк копии хранилища владельца (280 заметок, 190 журналов,
13 вложений — 4.3 МБ; `.rescue` в облако не едет): **2.9 с** на настоящий
wsgidav, из них шифрование 10 мс. С синтетикой до 500 МБ — **7.7 с**,
шифрование 693 мс (**1.27 ГБ/с**). Оверхед обёртки: 0.3 % на журналах,
0.004 % на картинках. Шифрование не узкое место ни на каком масштабе.

Argon2id на машине владельца: 512 МиБ × 4 прохода ≈ 1.5 с (его порог).
