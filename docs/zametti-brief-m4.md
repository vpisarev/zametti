# Zametti — бриф для Claude Code, этап 4: три панели, поиск, внешний редактор

## Контекст

Этапы 1–3 закрыты: ядро с инвариантами идемпотентности, WYSIWYG-редактор,
плоское хранилище `<id>.md` с метаданными в HTML-комментарии и ролями
(`note` / `folder` / `trash`). Обязательное чтение: все предыдущие брифы и
отчёты (`zametti-brief-m1..m3.md`, `zametti-core-notes.md`,
`zametti-editor-notes.md`, отчёты этапов) — решения оттуда не повторяются.

Этот этап — про ежедневное использование: интерфейс в три панели, поиск,
выход во внешний редактор. Ядро не меняется вовсе; красный класс фаззеров
(дословные куски под правками) известен, отгорожен и здесь не чинится.

## Цель этапа

1. Трёхпанельный интерфейс: папки → плоский список заметок поддерева → заметка.
2. Поиск: `Ctrl+F` (в заметке), `Ctrl+H` (замена в заметке),
   `Ctrl+Shift+F` (по всем заметкам) со списком результатов и навигацией.
3. Открытие заметки во внешнем редакторе с безопасной обработкой метаданных.

## Не-цели

- регэкспы в поиске (UI проектируется так, чтобы тумблер добавился позже,
  но не реализуется); глобальная замена `Ctrl+Shift+H`;
- индекс поиска (FTS5 и любой другой) — только по результату замера;
- сохранение истории поисковых запросов между сеансами;
- история заметок, вставка картинок, запуск блоков кода, синхронизация;
- правки ядра и канона.

Не-цели — это не пожелания. Кажется, что без чего-то не обойтись, —
остановиться и спросить.

## Первая задача: замер

До кода поиска — измерить на реальном хранилище (266 заметок, ~5 МБ):
холодный и тёплый полный проход «прочитать все файлы + parse + поиск
подстроки по тексту блоков». Числа — в отчёт. Ожидание — десятки миллисекунд
в тёплом; от результата зависят дебаунс as-you-type и (при катастрофе,
которой не ждём) возврат к разговору об индексе. Заодно замерить извлечение
сниппетов для средней колонки при старте.

## Три панели

### Левая: только папки

- Дерево заметок с `role: folder`; обычные заметки в левой панели не
  показываются.
- Корневой узел — всегда первый и всегда виден: подпись — имя хранилища из
  конфига, при его отсутствии «All notes». Выбор корня = все заметки
  хранилища.
- Существующие операции над папками (создание, переименование, перенос,
  корзина) продолжают работать здесь же.
- Тело самой заметки-папки в среднюю колонку не попадает (см. ниже);
  для его просмотра и правки — пункт контекстного меню «Открыть как заметку»
  (открывает в правой панели). Ожидается, что тела папок почти всегда пусты.

### Средняя: плоский список заметок поддерева

- Все заметки (`role: note`) из **всего поддерева** выбранной папки, без
  группировки по подпапкам.
- Строка списка: заголовок + 2–3 строки контента + дата изменения (короткий
  формат: сегодня — время, в этом году — «14 мар», иначе — «14.03.2019»).
- Сниппет: первые непустые текстовые строки тела **после** заголовка, из
  текста IR (без markdown-маркеров, метаданных и VSpace); блоки кода
  участвуют как текст; обрезка по длине с многоточием. Сниппеты
  извлекаются при сканировании и обновляются при сохранении заметки и при
  внешнем изменении — без пере-парсинга всего хранилища на каждый чих.
- Выбор строки открывает заметку в правой панели; ↑/↓ ходят по списку не
  отбирая фокус ввода у редактора насовсем (как в Apple Notes: список
  держит выбор, редактирование — по клику/Enter в правой).
- `Ctrl+N` создаёт заметку в выбранной папке и ставит курсор в заголовок.
- Контекстное меню строки: перенос в папку, корзина, «Открыть во внешнем
  редакторе» (см. ниже). Перетаскивание строки на папку левой панели =
  перенос.

### Сортировка — одна на обе панели

- Режимы: **по имени** (заголовок, локале-зависимое сравнение,
  `QCollator`) и **по дате изменения** (свежие сверху). Переключатель —
  небольшой контрол над средней колонкой; выбор сохраняется в состоянии.
- В режиме «по дате» папки левой панели сортируются по **максимальному
  `modified` своего поддерева** — папка со свежей заметкой всплывает
  (поведение Apple Notes).
- Корень «All notes» закреплён первым в любом режиме.
- Смена заголовка/`modified` при сохранении обновляет и строку списка, и
  позицию в сортировке (существующее автообновление узла дерева
  расширяется на среднюю колонку).

### Правая: редактор

Без изменений. Восстановление позиции курсора при переключении заметок —
из todo, если уже сделано — не трогать; если нет — сделать здесь (это
поведение средней колонки).

## Поиск

Общие принципы:

- **Поиск видит то, что видит пользователь**: искомая единица — текст
  блоков IR / документа. Метаданные, markdown-маркеры, синтаксис эмфазиса
  не ищутся. Совпадение не пересекает границу блока — это осознанное
  ограничение, зафиксировать в справке.
- **Smart case**: запрос целиком в нижнем регистре → регистронезависимо;
  есть хоть одна заглавная → регистрозависимо. Сравнение юникодное
  (кириллица обязана работать; наивный ASCII-tolower — баг), через
  `QString`-фолдинг.
- Поле ввода одно и то же по конструкции для всех трёх команд (нижняя
  немодальная панель в стиле Sublime); `Ctrl+H` добавляет поле «заменить
  на», `Ctrl+Shift+F` — список результатов. `Esc` закрывает панель и
  снимает подсветку.

### `Ctrl+F` — в открытой заметке

- As-you-type, подсветка всех вхождений тонировкой (машинерия тонировки
  выделения уже есть), текущее — контрастнее; счётчик «3/17».
- `Enter`/`F3` — следующее, `Shift+F3` — предыдущее, циклически; вид
  скроллится по правилу «футбольного арбитра» из этапа 2.

### `Ctrl+H` — замена в открытой заметке

- Та же панель + поле замены. «Заменить» (текущее и перейти к следующему),
  «Заменить все».
- «Заменить все» — один edit block, один шаг undo.
- Замена работает в текстах блоков, включая rawSource-блоки (они —
  литеральный текст); метаданных не касается по построению.

### `Ctrl+Shift+F` — по всем заметкам

- Панель поиска + под ней список результатов: строки вида «заголовок
  заметки — фрагмент строки с совпадением» (совпадение подсвечено),
  несколько совпадений одной заметки — отдельными строками, сгруппированы
  под заголовком.
- As-you-type с дебаунсом (значение — по замеру), **исполнение вне
  UI-потока**: новый запрос отменяет предыдущий (отмена проверяется между
  файлами). Пустой запрос очищает список. Это архитектурное требование —
  оно переживёт и рост корпуса, и будущий тумблер регэкспов.
- Клик по результату — открыть заметку в правой панели, проскроллить к
  совпадению, выделить его. `F3`/`Shift+F3` при открытой глобальной панели
  ходят по списку результатов циклически, открывая заметки по мере надобности.
- Правило разрешения `F3`: действует та поисковая панель, что открыта
  (открытие одной закрывает другую).
- Запрос короче 2 символов не исполняется (шумовой порог).

## Внешний редактор

Пункт контекстного меню заметки (в средней колонке и на вкладке правой
панели): «Открыть во внешнем редакторе».

- Команда — параметр конфига `external_editor` с плейсхолдером `%f`
  (например `gedit %f`, `code -g %f`); по умолчанию, при пустом значении —
  `xdg-open`. Терминальные редакторы — забота пользователя (он впишет
  свой запуск терминала).
- Открывается **настоящий файл хранилища, целиком, включая блок
  метаданных**. Никаких временных копий и «очищенных» экспортов: инвариант
  «файл правится чем угодно» — основа всего формата, и метаданные-комментарий
  выбраны именно за то, что переживают чужие редакторы.

### Решение по метаданным: доверять и чинить, а не прятать

Внешний редактор **может** править метаданные — это не дыра, а функция
(правка `parent` руками = перенос заметки). Защита — на приёме, через уже
существующую машинерию внешних изменений этапа 2:

- файл изменился снаружи → существующее поведение (undoable-правка либо
  диалог при несохранённых правках) сохраняется;
- после перечитывания метаданные валидируются. Битый или удалённый блок
  метаданных — **не тихая деградация**: приложение знает прежние значения
  (`parent`, `created`, `tags` в модели) и предлагает одним действием
  восстановить блок, сохранив правки тела; восстановление — обычное
  undoable-сохранение. Отказ пользователя — заметка живёт без метаданных
  до следующего решения (в корне, `created` из прежней модели в памяти до
  перезапуска);
- `parent`, заменённый на валидный id, — легитимный перенос, дерево и
  средняя колонка обновляются; невалидный id — существующее поведение
  загрузчика (в корень с пометкой, файл не переписывается);
- `modified` не критичен: обновится при следующем сохранении из приложения.

Опционально (по желанию, не обязательство): для редакторов с синтаксисом
`+строка` (`vim`, `code -g file:line`) — второй плейсхолдер `%l` с номером
строки текущего блока (сериализатор знает соответствие блоков строкам).

## Инварианты и тесты

```
A. Поиск не читает и не находит метаданные и markdown-маркеры
B. Глобальный поиск никогда не блокирует UI-поток
C. Внешняя правка не приводит к тихой потере метаданных: либо валидны,
   либо предложено восстановление
```

Обязательные тесты:

- smart case: «дом»/«Дом» на кириллическом корпусе; юникодный фолдинг;
- поиск по тексту блоков: запрос «2019» не находит `created:`; запрос
  «жирный» находит текст внутри `**…**`; совпадение через границу блока
  не находится;
- отмена глобального поиска: длинный запрос отменяется новым, результатов
  первого в списке нет;
- «Заменить все» — один шаг undo; замена в rawSource-блоке сохраняет
  дословность остального;
- средняя колонка: плоскость (заметка из под-под-папки видна), сниппет без
  маркеров и метаданных, папки в списке отсутствуют, тело папки доступно
  через «Открыть как заметку»;
- сортировка: по имени с `QCollator` (кириллица), по дате с всплытием
  папки по максимуму поддерева, корень всегда первый;
- смена заголовка → строка списка и позиция сортировки обновляются;
- внешний редактор: правка тела (метаданные целы) → штатное перечитывание;
  удаление блока метаданных → предложение восстановления, тело сохранено;
  `parent` → валидный id → заметка переехала; `--` внутри значения не
  ломает разбор соседних заметок;
- замер из «Первой задачи» — числа в отчёте.

Критерий приёмки глазами (урок этапа 3): открыть реальное хранилище,
выбрать «All notes», сортировка по дате — средняя колонка читается как в
Apple Notes: заголовок, две строки текста без символов разметки, свежее
сверху; найти глазами заметку по обрывку фразы через `Ctrl+Shift+F` и
попасть кликом точно в место.

## Правила работы

- Ничего за пределами репозитория не трогать; рабочее хранилище владельца —
  только чтение, тесты — на копиях и фикстурах в каталоге сборки.
- Секция «Мои ошибки» в отчёте обязательна.
- Измерять, а не рассуждать; простое решение предпочтительнее общего.
- Сомнение — повод спросить, а не додумать.
