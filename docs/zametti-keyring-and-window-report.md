# Отчёт: keyring Linux/Windows на свёртке + окно хранилищ (31.08.2026)

Сессия по брифу владельца 31.08 (глюки окна хранилищ на Linux + «сделать
keyring как на маке») с живыми пробами владельца по ходу и уточнениями a–h.

## Окно хранилищ

- **Двойное многоточие Browse**: модель отдавала label «…», а кнопка уже несёт
  иконку ellipsis — рисовалось «[•••] …». Подпись убрана из модели.
- **Глаз пароля шифрования** был мёртв навсегда у хранилищ, подключённых до
  третьей записи связки: кружочки (stub) включала запись КЛЮЧА, а eyeEnabled —
  отдельная запись ПАРОЛЯ (её у старых хранилищ нет). Новая грамматика:
  **кружочки обещают ровно то, что глаз умеет показать** — обе стороны от
  записи пароля. Старое хранилище: поле пустое, СЕРЫЙ «not on this device»
  (решение владельца), тревога осталась про ключ — облаку хватает ключа, и
  `encryptionFromKeyring` в работе как был. Лямбда глаза: набранное
  показывается без чтения связки (прежде затиралось хранимым); отказ связки
  глаз не открывает — литеральные «•» заглушки не могут показаться «текстом
  пароля», при рассинхроне поле пересинхронизируется render()-ом.
- **eye-closed вместо eye-off** (решение владельца: кружочки — глаз закрыт,
  нажали — открыт). Иконка кнопки QLineEdit-действия состояний QIcon::On/Off
  НЕ рисует (живая проба владельца: глаз «не открывался») — иконка меняется
  руками в toggled.
- **Косметика по разбору диалога** (docs/zametti-storages-dialog-refactoring.md,
  выбор владельца + уточнения живых проб): галочка открытого — иконкой lucide
  check в общей иконной колонке (имена всех строк по буквам, воздух справа);
  «+ −» — маленькие квадратные (шириной; высоту не фиксируем — мак режет
  бэзель) в футере списка за слабой чертой; Close без красного креста; форма —
  секции **Local** / **Cloud synchronization** с чертой и воздухом между ними,
  оба пути зовутся **Folder**; подписи полей по правому краю; рамки фактов
  сняты — просто текст, хвост (дата) приглушён цветом палитры, резерв высоты в
  две строки сохранён; строка события отодвинута на высоту строки.
- **Строки фактов без префиксов** «Local:»/«Cloud:» (секция уже сказала, чей
  факт) и **человеческая дата** `yyyy-MM-dd HH:mm` в показе — ISO-8601 с
  офсетом остаётся правилом шапок файлов, сравнения по UTC как были.
- **Авто-Check** (`maybeAutoCheck`): пароль сервера в связке (заглушка, не
  набран) + названное облако + «в этом окне ещё не ходили» → проверка
  выполняется сама при выборе строки и первом показе. Набранный пароль и уже
  проверенный адрес не дёргают; повторно не стреляет (окно помнит seen).
- Матрица окна дополнена: четвёртая строка состояний поля пароля, пометка о
  косметике 31.08.

## Keyring: Linux и Windows на маковской схеме

Ярусы 1–2 (CBOR-свёрток `secret_bundle`, правила `BundledSecrets`) — как были,
платформенно-чистые; их покрытие (`bundled_secrets_test`) новые ветки
наследуют автоматически. Написаны ярусы 3:

- **Linux (`DbusBundle`)**: один item `{application: zametti, kind: bundle}`,
  метка `zametti-secrets`; индекс — атрибутом `index` (base64 CBOR: a{ss}
  несёт только строки). Запись НЕ пересоздаётся: `Item.SetSecret` +
  `Properties.Set` на найденном пути, CreateItem — только первый раз. `has()`
  — по индексу, без GetSecret и без Unlock. `available()` отвечает «нет» и на
  ЗАПЕРТУЮ коллекцию: индекс запертой записи может быть нечитаем (открытая
  часть файла gnome-keyring несёт хеши атрибутов), и «нет записи» из него
  зажгло бы ложные красные требования; Unknown честнее. Фолбэк коллекции:
  default → login по пути → первая не-session; коллекций не создаём, SetAlias
  не зовём.
- **Windows (`WinCredBundle`)**: один credential `zametti-secrets`, индекс —
  кусками `index0..N` в CredentialAttributes; CredWriteW перезаписывает на
  месте (ACL-беды мака нет). `kMaxBlob = 5*512` СВОЕЙ константой: mingw несёт
  устаревшие 512, реальный лимит ОС 2560 (пробник подтверждает записью).
  Свёрток ~120–140 байт на хранилище — больше десятка влезает; план Б (резка
  на `zametti-secrets-<n>`) записан здесь, не в коде. Фолбэк readIndex: если
  атрибутов нет (wine не хранит их вовсе — замер) — индекс из самого свёртка;
  на Windows чтение блоба вопросов не поднимает, доктрина «индекс без данных»
  — про вопросы.
- **Миграция** запись-на-секрет → свёрток — в платформенных дверях, при первом
  чтении (на Windows — и индексном: вопросов не бывает): старые записи
  собираются в свёрток и ПОСЛЕ удачной записи удаляются (решение владельца) —
  оставленные, они лгали бы витрине связки и воскресали при откате версии.

### Пробник (`zametti-bench keyring`)

- Linux-ветка: состояние связки (видна/заперта — печатается причина, по
  которой available() говорит «нет»); замер «читаются ли атрибуты у запертой»
  — только если коллекция уже заперта (запирать связку владельца пробник не
  смеет); миграция на выдуманном storeId с подчисткой. На запертой связке
  честно останавливается, Unlock не зовёт.
- Windows-ветка: лимит 2560 записью; миграция. Обе ветки пропускают замер
  миграции, если свёрток уже есть (мигрируют только связки без него, удалять
  живой свёрток нельзя).
- **Wine-прогоны** (кросс-сборка build-win): чистый префикс — лимит верен,
  миграция собрала свёрток, legacy исчезла, has() отвечает (через фолбэк:
  wine не хранит атрибуты); полная приёмка ключ/пароль зелёная. Wine ≠
  гарантия настоящего Windows — живой прогон остаётся долгом ниже.

### Живая машина владельца (Linux)

`~/.local/share/keyrings/login.keyring` — пустая (0 записей), создана агентом
24.08 с паролем ≠ паролю входа; `ReadAlias("default")` отвечает login, но
коллекция ЗАПЕРТА, PAM её не отпирает — отсюда прежние вопросы пароля.
**Решение владельца: связку не трогаем.** Пробник на этой машине печатает:
«login, ЗАПЕРТА … НЕ ИЗМЕРЕНО — записей zametti нет», ни одного системного
вопроса. Полная живая приёмка Linux — когда/если владелец пересоздаст связку
(рецепт: закрыть приложения, удалить login.keyring руками, перелогиниться —
pam_gnome_keyring создаст её с паролем входа и будет отпирать сам).

## Долги и что осталось

- **FuzzOps красный ДО сессии** (проверено бинарём build-r1 от 26.08 на том же
  корпусе): «заметка записывается» на файлах корпуса Apple Notes с inline-code
  спанами. Не из зоны этой сессии; корпус, судя по некоммиченному
  testdata.tar, свежий — вопрос владельцу, чинить ли здесь или это известный
  хвост корпуса.
- Настоящий Windows: пробник (лимит, миграция, «второй прогон»), живое окно.
- Замер «атрибуты у запертой» на Linux не измерен (в запертой связке нет
  записей zametti) — стойка в пробнике ждёт случая; страховка available() всё
  равно закрывает оба исхода.
- Release-сборка build-r1 не собиралась с 26.08 (-Werror: хвостовые «\» в
  комментариях, nodiscard open) — починено здесь же, три места.

## Мои ошибки

1. **Тест «кружочки-заглушка не стали текстом» был написан не о том**: после
   отказа связки заглушка вправе остаться в поле ПОД МАСКОЙ (факты
   закэшированы), беда только в echo Normal. Ассерт по букве («в text() нет
   •») падал на законном поведении — переформулировал на echo.
2. **Первая редакция моей же лямбды глаза открыла бы дыру рассинхрона**
   (заглушка в поле при свежем не-stub снимке → «показать набранное» открыло
   бы кружочки) — поймал при написании теста, ветка ужесточена до отказа.
3. **Миграционный замер пробника упал под wine на второй раз**: не подумал,
   что первый дым уже оставил свёрток, а миграция по построению идёт только
   без него. Урок: сценарий пробника обязан оговаривать состояние связки; обе
   ветки теперь честно печатают «НЕ ИЗМЕРЕНО — свёрток уже есть».
4. **«has() по атрибутам» на Windows держался на непроверенном допущении**,
   что атрибуты хранятся везде: wine их не хранит вовсе. Фолбэк из свёртка
   закрыл класс бед, а не один случай.
5. Ошибки с git при проверке красноты (стёртый некоммиченный тест, застейдженный
   revert в чужом коммите) — разобраны в отчёте по маркерам.
