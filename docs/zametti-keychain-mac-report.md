# Отчёт: Keychain на macOS — секреты одной записью-свёртком

30.08.2026. Заказ владельца: на маке (а в будущем — на всех системах) все
секреты синка лежат в связке устройства ОДНОЙ записью-свёртком, не
записью-на-секрет, как сегодня у dbus/wincred. До этой работы мак стоял на
заглушке — секреты не хранились нигде.

## Что сделано

1. **`SecretStore::has()`** — новая дверь интерфейса: «есть ли секрет», не
   читая его (довод §1.2 восстановленной матрицы окна хранилищ; замер ниже).
   Воплощения: env — переменная непуста; dbus — SearchItems без GetSecret и
   без Unlock; wincred — CredReadW ради факта; stub и копилка TakenSecrets —
   честное «нет». Наборы пересажены на общий `tests/fake_secrets.h`
   (восстановлен из `.recovery` дословно, счётчики asked/reads) — прежде та
   же подделка лежала в двух наборах слово в слово.
2. **`SecretBundle`** (`sync/secret_bundle.{h,cpp}`) — формат свёртка: CBOR
   `{v:1, stores:{storeId:{слот:байты}}}`, слоты именованные («key»,
   «webdav», «password» — словарь общий с dbus/wincred), незнакомый слот
   переживает нашу запись, версия выше своей отвергается. Индекс — та же
   карта БЕЗ секретов, для has().
3. **`BundledSecrets`** (`sync/bundled_secrets.{h,cpp}`) — правила одной
   записи; .cpp — уцелевший файл утраченной сессии 29–30.08, байт в байт.
   Правила: свёрток читается раз за прогон; читаем-перед-записью; has() по
   индексу; убранный секрет — пустой слот, запись НЕ удаляется.
4. **`sync/keyring_secrets_keychain.cpp`** — мак: двери над SecItem*.
   Запись kSecClassGenericPassword, service/метка `io.zametti.zametti`,
   account `secrets`; свёрток в данных, индекс в `kSecAttrGeneric`;
   writeBundle — SecItemUpdate, SecItemAdd только для первой записи в жизни
   устройства; iCloud (kSecAttrSynchronizable) не ставится. `KeyringSecrets`
   пробрасывает; stub остался системам без своей ветки.
5. **Наборы**: `bundled_secrets_test` — двери подменены памятью со
   счётчиками; краснота проверена снятием починок целиком (has-через-свёрток
   и снятый кэш — обе проверки краснеют). Полный `zametti-tests`: зелёный,
   кроме `Zstd` и `FuzzOps` — они красные на маке с до-переносимых времён
   (см. `zametti-build-macos.md`, «Долги»), к секретам отношения не имеют.
6. **Пробник** `zametti-bench keyring`: маковская ветка сырыми SecItem* с
   подсказками «следите за экраном», `--keep` оставляет запись следующему
   прогону — так меряется сценарий «после пересборки».

## Замер политики вопросов (владелец у экрана, 30.08.2026)

Требование владельца: максимум ОДИН вопрос после пересборки; потом — никогда,
включая перезагрузки; на новой машине — один раз.

| сценарий | вопросов |
|---|---|
| свой процесс создал и читает (атрибуты, данные, update, delete) | **0** |
| повторный прогон того же бинаря | **0** |
| чужой бинарь (другая сборка): чтение ОДНИХ АТРИБУТОВ | **0** — шаг допечатался до зависания |
| чужой бинарь: чтение ДАННЫХ | **1** (диалог висел до ответа человека) |
| ещё одна новая сборка | снова 1 — по одному на каждую |

Выводы, на которых стоит код: has() по атрибутам БЕЗ вопросов — можно звать
на каждое переключение строки; чтение свёртка — раз за прогон (вопрос, если
будет, один); запись не пересоздавать (ACL). Ad-hoc подпись даёт новый
отпечаток на каждую пересборку — один вопрос после пересборки без
Developer ID неустраним, и это разрешённый максимум владельца.

## Мои ошибки

1. **Сравнение в пробнике не пережило собственный `--keep`**: запись
   остаётся с байтами шага 4 (обновление), а следующий прогон ждал байты
   шага 1 — замер «после пересборки» упал на «данные вернулись не те».
   Починено: законны оба содержимых. Урок: режим, который сам оставляет
   след, обязан уметь читать СВОЙ след.
2. **`slots` — макрос Qt**: переменная с этим именем в secret_bundle.cpp не
   компилируется. Переименована с комментарием.
3. **`mv` вернул файлу старый mtime** при проверке красноты — make счёл
   объект свежим, и «восстановленный» набор красным остался от СТАРОГО
   бинаря. Поймано, потому что красный после восстановления — это
   неожиданность, которой надо верить; `touch` + пересборка дали зелёный.
4. Забыл, что `Keyfile::key()`/`fromLiveKey` закрыты — BundledSecrets
   добавлен в друзья Keyfile (он и есть «воплощение связки» из комментария),
   а в наборе сверка ключей идёт печатью шифра, не байтами.

## Не сделано / оговорки

- dbus/wincred остаются per-secret; их переезд на свёрток — следующие заходы
  (направление записано в CMake и заголовках). Их has() написан вслепую:
  linux/windows здесь не компилируются — **не гонялись**.
- UI кружочков и западающего глаза — отдельная работа окна хранилищ;
  интерфейс под неё готов.
- Боевая запись `io.zametti.zametti` живёт и пустой — это по построению
  (удаление сбросило бы ACL).
- iCloud Keychain — отдельно, дефолт ВЫКЛ.
