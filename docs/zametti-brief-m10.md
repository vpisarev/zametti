# Zametti — бриф для Claude Code, этап 10: история v3 и каскад картинок

## Контекст

Этапы 1–9 закрыты. Журнал живёт (этап 7), правила эквивалентности и
схлопывания хвоста живут (этап 9, раздел «История»); этот этап — ленивая
чистка всей накопленной истории, визуализация изменений, поиск в истории и
жизненный цикл картинок при удалении заметок.

Обязательное чтение: `zametti-m7-report.md`, раздел «История» в
`zametti-m9-report.md`, `zametti-storage.md`.

## Цель этапа

1. Версия журнала + ленивая миграция: старые журналы чистятся от дубликатов
   при первой же записи, без глобальной утилиты.
2. Дифф-визуализация: два вида поверх одного механизма (DTL).
3. Поиск: внутри слепка (Ctrl+F в режиме истории) и по истории текущей
   заметки.
4. Каскад картинок: вложения следуют за заметкой в корзину и обратно;
   физическое расставание — только при очистке корзины.
5. `zametti-store history compress` — тестовый люк миграции для работы без UI.

## Не-цели

- **поиск по истории всех заметок** — отложен (решение владельца:
  пер-заметочный сильно быстрее и более востребован; корпусный добавим позже,
  механизм кладётся так, чтобы на него расширяться);
- ручная чистка истории пользователем (кроме тестового люка) — единственный
  штатный путь чистки это ленивая миграция;
- раздел «картинки-сироты» (удалили картинку из живой заметки — пока ничего,
  решение владельца «дальше придумаем»);
- перескок вешек External, укорачивание сверх правил — как и раньше, никогда;
- диалоги подтверждения где бы то ни было («а вы уверены?» — не наш стиль:
  предохранитель это undo и ступени корзины, а не вопросы);
- синхронизация; запуск блоков кода.

## Часть 1: версия журнала и ленивая миграция

Заголовок журнала (первая CBOR-запись этапа 7) уже несёт номер версии —
номер получает семантику:

- журнал без осмысленной версии = **v0** («не чищен»);
- **v0.1** = «история чищена по правилам этапа 9».

Миграция:

- **триггеров два, оба пер-заметочные**: (а) первая запись в журнал (любое
  автосохранение правки); (б) первое **чтение журнала ради истории этой
  заметки** — Ctrl+Z, вход в режим истории (поправка владельца: чистить и на
  чтении — удобнее, чем править заметку ради чистки). Просто просмотр заметки
  журнал не трогает вовсе;
- **корпусные читатели НЕ переписывают журналы никогда**: `verify` (и будущий
  глобальный поиск по истории) читают как есть — иначе первый же поиск стал бы «той
  самой глобальной утилитой» через чёрный ход. Чистоту показа они получают
  тем же чистым ядром миграции, применённым в памяти. Отсюда устройство:
  ядро (записи → записи, чистая функция) + обёртка с атомарной перезаписью;
  обёртку зовут только пер-заметочные входы;
- навигация к записи — по (время, хеш): если точная запись вычищена
  миграцией как дубликат, целью становится выжившая равная (содержимое у
  дубликатов одно);
- v0 → полная пересборка: удаление дубликатов (равенство слепков без учёта
  строки `modified`) и почти-дубликатов (правила слияния и схлопывания
  этапа 9), затем версия 0.1, затем обычная работа (дописывание или показ).
  Пересборка — атомарно (temp + rename), тем же путём, что прореживание;
- v0.1+ → ничего, обычное дописывание со всеми живыми проверками;
- **два режима чистки различаются сторожем свежести, и это записывается в
  код явно**: живое схлопывание (этап 9) работает только по свежим записям;
  миграция чистит ретроактивно, на возраст не глядя — иначе старые дубликаты
  не вычистятся никогда. Общие для обоих режимов границы неприкосновенны:
  только обычные сохранения, вешки External не перепрыгиваются, опорная
  запись, tombstone и последняя запись не удаляются;
- идемпотентность: повторная миграция (форсом) не меняет ни байта.

### Тестовый люк

```
zametti-store history compress <id | путь к .md>
```

Форсирует **ту же функцию миграции** на одном журнале — не параллельную
реализацию, а боевой путь. Вывод: версия до/после, сколько записей удалено и
схлопнуто. Существует исключительно для тестирования функционала без UI.

### Фикстура из жизни

Владелец нашёл в «Пробуем Obsidian» настоящие дубликаты (записи 0–3, 4–6,
пары 9/11 и 10/12). Скопировать этот журнал в `.testdata/` (хранилище
владельца — только чтение!) и сделать эталонным тестом миграции: ожидаемый
результат схлопывания записан явно.

## Часть 2: дифф

### Механизм — один

- **DTL** (header-only, Майерс) вендорится с лицензией — четвёртая
  микробиблиотека после md4c/blake3/zstd;
- единица сравнения — **строки канонического сериализованного markdown**
  обоих слепков; соответствие «строка ↔ блок» — существующая машинерия
  полосы сведений;
- база сравнения — переключатель из двух состояний: **«с предыдущей
  записью» (дефолт)** и «со свежей версией». Кнопка «Вернуть» никакого
  диффа и никаких вопросов не показывает — восстановление и есть
  восстановление (предохранитель — undo).

### Два вида поверх него

Оба вида показывают **весь документ целиком**; нетронутое не подкрашено —
полный контекст всегда (решение владельца: настоящие diff-файлы дают слишком
мало контекста).

- **V2, plain** (строится первым): моноширинный markdown, зоны зелёные
  (добавлено) / красные (удалено) / оранжевые (изменено). Точный вид «под
  капотом»;
- **V1, WYSIWYG** (флагман): обычный рендер слепка + цветные полоски на поле
  сбоку от блока (рисование по геометрии блока — как маркеры): зелёная —
  добавлен, оранжевая — изменён; удалённое, которого в документе нет, —
  **вставка-заглушка** «*N строк удалено*» с красной полоской. Разворот
  заглушки по клику (read-only, красный фон) — можно, но не обязательство;
- **Tab** переключает виды; позиция и прокрутка сохраняются (одно
  пространство строк);
- **Alt — удержание**: пока держишь, показывается вторая сторона сравнения,
  отпустил — вернулась первая (блинк-компаратор; глаз ловит изменение
  миганием лучше, чем памятью). Не переключатель — именно удержание;
- **F4 / Shift+F4** — следующий/предыдущий изменённый блок, циклически.
  Пара живёт в конфиге (раздел `shortcuts`, дефолт F4/Shift+F4) — мак
  выберет свой аккорд при портировании правкой конфига;
- **V2 — эталон V1**: набор изменённых строк обязан совпадать между видами,
  расхождение = баг маппинга. Это тест, гоняемый на корпусе.

## Часть 2.5: кнопка входа в историю

На тулбар возвращается **одна** кнопка истории (`rotate-ccw-clock`, «часы со
стрелкой») — прямой вход в историю заметки, минуя внутридокументный стек:
после правок Ctrl+Z-проваливание требует размотать свои же правки, кнопка —
вторая дверь (решение владельца).

- **вход = ещё одна точка сохранения** (в списке этапа 9 рядом с «уход из
  заметки»): try-save со всеми правилами отбора → вершина таймлайна — не
  виртуальный «буфер», а настоящая головная запись, равная ему (не
  изменилось — записи нет, голова и так равна). «Вернуть» на вершине честно
  отказывается, дифф «со свежей» сравнивает с реальной записью;
- вход — пер-заметочное обращение к истории: миграция v0 срабатывает;
- **выход из истории возвращает живой буфер с нетронутым стеком отмены** —
  именованный инвариант: режим истории живой документ не трогает, после
  «к последней» Ctrl+Z продолжает отматывать до-исторические правки.

## Часть 3: поиск

- **Внутри слепка**: Ctrl+F / F3 / Shift+F3 работают в режиме истории по
  показанному слепку (read-only поиску не помеха; замена задизейблена).
  F3 остаётся за поиском — прыжки по диффу на F4;
- **раскладка в режиме истории симметрична обычной**: Ctrl+F — по показанному
  слепку («по открытому документу»), Ctrl+Shift+F — по всем слепкам заметки
  (аналог «шире документа»; корпусный смысл в истории не в тему). Кнопка
  истории поиск НЕ активирует — только открывает режим; F3 ходит по находкам
  активного поиска;
- **по истории текущей заметки**: сборка всех слепков её журнала (пер-заметочно
  это миллисекунды) и поиск по каждому; результаты — список «дата слепка ·
  фрагмент», сгруппированный по записям; клик → режим истории на этом слепке с
  подсветкой найденного. Доступен и из обычного режима, и из режима истории;
  smart case и порог 2 символа — как во всём поиске. Это **пер-заметочное
  обращение к истории** — миграция v0-журнала срабатывает до поиска, искать по
  уже чистому;
- механизм писать расширяемым до корпусного прогона (отложен), но самого
  корпусного прогона в этапе нет.

## Часть 4: каскад картинок

Решение владельца: история при удалении **сознательно игнорируется** —
удаление радикально, предохранителей три (корзина → очистка корзины →
мусорка ОС), а слепки со ссылками на исчезнувшее деградируют штатной рамкой
«файл не найден» (этап 7).

Механика — **корзинность вложения выводится, а не хранится**:

```
вложение «в корзине» ⇔ все ссылающиеся на него заметки — в корзине
```

- перенос заметки в корзину / восстановление — над вложениями НЕ выполняется
  ничего: семантика владельца («картинки следуют за заметкой туда и
  обратно») получается автоматически, состояние не может рассинхронизироваться;
- заметки в корзине продолжают рендерить свои картинки (файлы на месте);
- **очистка корзины** — момент физического расставания: для каждого вложения
  очищаемых заметок — **байтовый поиск id** (14 символов, парсинг не нужен)
  по всем остающимся `.md`, живым и корзинным; внутренний цикл — по
  картинкам, каждая заметка читается один раз. Не найдено нигде → файл
  вложения уезжает в мусорку ОС вместе с заметками. Ложное срабатывание
  (id текстом в блоке кода) ошибается в безопасную сторону — файл остаётся;
- `verify` приводится к новой доктрине: сирота = вложение, не упомянутое ни
  в одной заметке вовсе (живой или корзинной); «упомянуто только в корзине» —
  информационная строка «уйдёт с очисткой», не аномалия; битая ссылка из
  слепка истории — норма, не отчёт.

## Инварианты и тесты

```
A. Миграция идемпотентна; опорная запись, tombstone, последняя запись живы;
   через External не схлопывается
B. Наборы изменённых строк V1 и V2 совпадают (сверка на корпусе)
C. Файл вложения покидает хранилище только при очистке корзины и только
   если его id не найден ни в одной остающейся заметке
D. Восстановление заметки возвращает её картинки без единой операции над
   ними (выводимость корзинности)
```

- фикстура «Пробуем Obsidian»: ожидаемое схлопывание записано явно;
- миграция: v0 → 0.1 и по записи, и по Ctrl+Z (файл переписан до первого
  шага); `verify` НЕ меняет mtime ни одного журнала (проверка по всем);
  поиск по истории заметки сперва мигрирует её журнал (v0 → 0.1), результаты
  считаются по чистому; адресация записей — по (время, хеш); повторный форс — ноль изменений; External-вешка
  посреди дубликатов останавливает схлопывание; последняя запись и
  tombstone неприкосновенны;
- дифф: добавление / удаление / изменение / del+add при перестановке;
  большая заметка (Ficus Tutorial из тестовых); заглушка «N строк удалено»;
  Alt-подглядывание (снимок с зажатым и отпущенным); Tab сохраняет позицию;
  F4-циклы; переключатель базы;
- кнопка истории: вход с грязным буфером порождает запись (с чистым — нет);
  выход → Ctrl+Z отменяет до-исторические правки (стек цел); вход мигрирует
  v0-журнал;
- поиск: Ctrl+F в слепке; по истории заметки — находит текст, существующий
  только в старом слепке, клик открывает историю в нужном месте;
- каскад: картинка общая для двух заметок (одна в корзину → файл на месте;
  обе → уходит при очистке); id текстом в кодовом блоке третьей заметки →
  остаётся; восстановление возвращает; `verify` — три категории;
- Xvfb-снимки: V1 с полосками и заглушкой, V2, тот же слепок с зажатым Alt.

Критерий глазами: открыть старую заметку с дубликатами → поправить букву →
история очистилась сама; пройтись по слепкам — полоски и заглушки читаются с
одного взгляда, Alt мигает состояниями, F4 водит по изменениям; найти поиском по истории
заметки фразу, которой в ней давно нет; удалить
эксперимент с двадцатью фотографиями, очистить корзину — хранилище похудело,
общая с другой заметкой картинка жива.

## Правила работы

- Ничего за пределами репозитория; хранилище владельца — только чтение
  (фикстуры — копиями в `.testdata/`); тип сборки и файлы владельца
  оставлять как нашёл.
- Широкое окно в матрице UI-тестов; Debug и Release; снимки Xvfb как
  артефакт приёмки.
- Эталонный счётный цикл возле замеров; прежде чем сравнивать минимумы —
  посмотреть на всю серию (урок этапа 9); каждая починка проверяется снятием.
- «Мои ошибки» обязательны. Измерять, а не рассуждать; сомнение — спросить.
