# Отчёт по этапу 3: плоское хранилище

Бриф — `docs/zametti-brief-m3.md`. Все семь задач закрыты, миграция корпуса
выполнена, хранилище живое: `zametti --root sandbox/vpnotes` (и просто
`zametti` — хранилище запоминается в state.json).

## Что сделано

### Ядро

- **Метаданные** (`<!-- zametti -->`) — слой в `Document::meta`: первый блок
  фиксированной формы поднимается из разбора, неизвестные ключи переживают
  круг побайтово, редактор метаданных не видит вовсе. `NoteMeta::unset` —
  перенос в корень это отсутствие `parent`.
- **`Kind::Divider`** — тематический разрыв, канон `___` (не конфликтует ни с
  setext, ни с буллетами); вход `---`/`***`/варианты приводится.
- **Image-спан** — `![alt](путь)` и `![alt](путь "title")`: подпись — текст
  спана, путь — href, title — только у картинки. Чего плоская модель не
  выражает (пустая подпись, разметка в подписи, картинка внутри разметки) —
  деградирует дословно, без потерь. Фрагмент пути `#w=N` — байты пути.
- **Комментарии — свой род** (`Kind::Html` × ось `HtmlKind`, пока единственное
  значение `Comment`; решение владельца — общий род для понятого HTML, вид
  осью): скобки — структура, повредить их правкой нельзя; внутренность — текст
  блока; живёт и внутри пункта; строчный комментарий — бит спана. Принцип,
  согласованный с владельцем: **HTML пускаем в модель словарём** — понятая
  конструкция получает род/спан и канон, непонятая дословна навсегда.
  Кандидат в словарь: цветной текст (`<span style="color:…">` → спан-ось).
- **Генератор id** — 14 знаков Crockford base32 без `i l o u`: 8 знаков
  unix-секунд big-endian + 6 CSPRNG; создание файла через `O_EXCL`
  (проверка и создание — одно действие ядра ОС), `EEXIST` — перегенерация.
  Эталон: `2019-03-14T09:26:53Z` → `01e8m7jx`. В логике id непрозрачен.

### Редактор

- Показ картинок: фото — «хитро-отрисованная строка», как черта. Текст строки
  не показывается никогда, пока строка — валидная картинка; выделение и
  каретка на строке — тонировка 50/50 поверх фото, не вскрытая разметка.
  Поддержаны канон и вики-вложения `![[путь|W]]` (только показ — модель
  вики-текст не трогает). Ресайз за любой из четырёх углов, ширина пишется
  операцией с историей: канону — `#w=` в путь, вики — `|W`. Ctrl+C/X кладут
  текстовое представление, Ctrl+V вставляет через полный парсер ядра.
  Backspace/Delete: фото — атом; пустая строка между фото и непустым текстом
  неудаляема (отказ + шаг, как у черты).
- Комментарии: Backspace в начале — жест снятия комментарности (буфер цел),
  Ctrl+/ — блок ↔ комментарий, построчно, как в редакторах кода.
- Нумерованные списки: вид номера по вложенности, три вида по кругу —
  `1.` → `a.` (биективно: z, aa…zz, aaa) → `1)`; в файле всегда `1.`.
- Ссылки: Ctrl+клик открывает адрес (замерено пробниками: встроенного
  открытия у редактируемого QTextBrowser в Qt 6.10 нет). Голый Ctrl больше
  не прокручивает вид. Окно про несохранение — галочка «больше не
  предупреждать про этот файл в этой сессии».

### Утилита `zametti-store`

`init` / `new` / `import` / `verify`; библиотека + тонкий CLI; импорт никогда
не пишет в источник.

- **Хранилище плоское до конца** (решение владельца, вместо `attachments/` с
  хеш-именами из брифа): вложения получают такие же 14-значные id и лежат в
  том же каталоге; дедупликация — по содержимому, внутри импорта. `init`
  заводит `.zametti/` (состояние), `.rescue/` (побитое; не синхронизируется)
  и `history/` (история; синхронизируется).
- **Пережатие при импорте**: png → webp без потерь (`cwebp`), heic → webp q90
  (`heif-convert` + `cwebp`), jpeg и webp — байт в байт; EXIF/ICC/XMP
  переезжают целиком (`-metadata all`, для heic — `exiftool` из исходника).
  Без кодека — копия как есть и беда в отчёте. Кодеки: `webp`,
  `libheif-examples`, `libheif-plugin-libde265`, `libimage-exiftool-perl`.
- **Вики-вложения усыновляются** построчно (как Ctrl+/): строка
  `![[путь|W]]` / `[[путь]]`, чья цель — существующий не-md файл, становится
  канонным image-спаном `![родное-имя](<id>.ext#w=W)`; прочие wikilinks не
  трогаются, только счёт.
- **Заголовки возвращаются всем заметкам** (первым блоком `# …`): Apple
  держит заголовок первой строкой, конвертер унёс его в имя файла, имя стало
  непрозрачным id. Источник заголовка — манифест (там он настоящий, с
  пунктуацией), иначе имя файла; не трогаются только заметки, где первый
  блок — заголовок ровно с тем же текстом.
- Времена: манифест → front matter → fs с пометкой; `created` кодируется в
  id. Ссылки на `.md` внутри набора → `<id>.md`. Отчёт соответствия — рядом
  с хранилищем (`<root>.import-report.txt`), молчаливых пропусков нет.
- `verify`: id-имена, метаданные, ноль дрейфа, `parent` и циклы, цели
  картинок, сироты в отчёт (не удалять).

### Манифест Apple Notes (JXA)

`tools/apple-notes-manifest.js` + инструкция `tools/apple-notes-manifest.md`.
Читает только имена и даты (быстро, запароленные заметки не мешают). Уроки
двух живых прогонов: `container()` папки на macOS не отдаёт родителя — корни
ищутся двумя проходами («кто ничей ребёнок»), пути собираются рекурсией вниз;
папка по умолчанию отображается в корень префикса. Сопоставление по
«папка + заголовок», с очисткой заголовков как у конвертера (`#`, `:`, `"`
удаляются, `/` → `-`, nbsp → пробел). Итог: 240/240 записей сопоставились.

### Приложение на плоском хранилище

- Дерево из метаданных: хранилище узнаётся по `.zametti` (и через `--root`,
  и при открытии любой `<id>.md`); свежие сверху по `modified` (у папки —
  максимум по поддереву), сортировка по имени — в контекстном меню; корзина
  внизу. Починка — только в памяти: сирота в корне с пометкой, цикл рвётся у
  виновника; загрузчик не пишет в файлы никогда (проверено байтами).
- **Заметка и папка не меняют ролей никогда** (правило владельца, заменившее
  бриф-формулу «каталог — заметка с детьми»): папка — `role: folder` в мете
  (у любой, пустой или нет), не открывается; создание целится в ближайшую
  папку; сброс перетаскиванием на заметку запрещён; папка в папку
  переносится, в своё поддерево — нет.
- Ctrl+N (открывает свежую заметку сразу), «Новая папка» (сразу в
  переименование), F2 (правит первый заголовок; живой заголовок обновляет
  дерево и титул окна без сохранения), перенос перетаскиванием.
- Удаление: пустая заметка/папка — сразу в корзину ОС (`moveToTrash`), без
  подтверждений; непустая — в заметочную корзину (`role: trash`); из корзины
  насовсем — с подтверждением, тоже через корзину ОС. Выделение уходит к
  соседу, корзина не раскрывается.
- `modified` обновляется при настоящем сохранении; rescue — в `.rescue/`;
  хранилище и сортировка запоминаются в state.json.

## Приёмка

- Живой корпус: **266 заметок + 15 вложений, `verify` зелёный, ноль дрейфа**;
  выборочные тела совпадают с `serialize(parse(источник))` байт в байт;
  244 файла + 22 каталога, скрытые (`.obsidian`) пропущены громко.
- Манифест: 240/240 сопоставлений, 0 неоднозначностей; даты настоящие
  (2016–2026), закодированы в id — `ls` сортирует хронологически.
- Тесты: 25/28 наборов зелёные; новые — note-id (814), store (38), tree (37),
  images (47); красными остались три давних fuzz-ops набора, и те лучше
  прежнего: 19/246/257 против 19/253/268 (картинки и комментарии перестали
  деградировать в дословные куски).

## Мои ошибки

1. **Повредил заметку владельца.** «Новая папка» по клику на заметке делала
   её родителем и штамповала `role: folder` — «Чем занять Claude» перестала
   открываться. Причина: я реализовал бриф-формулу «любая заметка может стать
   каталогом», не проверив её на живом сценарии. Данные починил руками,
   правило перевёрнуто, закреплено тестами (матрица сброса, байтовая
   неизменность). Урок: правило из брифа — тоже гипотеза.
2. **Дрейф пустой заметки, дважды.** `new` и импорт пустого файла писали
   пустую строку после `-->` — `verify` честно находил дрейф. Один и тот же
   урок наступил в двух местах, потому что канон пустой заметки я не замерил
   заранее, а вывел по жалобе.
3. **Ctrl+N не работал.** QTextEdit съедает сочетание через ShortcutOverride —
   я не прогнал сочетание живьём с фокусом в редакторе. Та же болезнь была у
   Ctrl+Z, и это было в истории проекта — не сопоставил.
4. **Дерево раскрывало корзину** после удаления (выделял перемещённую
   заметку), а Ctrl+N не открывал свежую (refreshTree глушит сигналы, я
   положился на выделение). Оба — непроверенные взаимодействия своих же
   частей.
5. **Первый JXA-прогон потерял вложенные папки**: понадеялся на `container()`
   вместо того, чтобы сразу строить пути рекурсией. Скрипт без мака под рукой
   — всё равно надо было писать защитно с первого раза.
6. **Инструментальные ляпы**: правка дважды улетала в
   `build/tests/CMakeLists.txt` (cwd после `cd build` — известная ловушка
   этого проекта); пустой срез в python-скрипте вставил мусор в начало
   `store.cpp`; ложный «DIFF» в приёмке из-за небрежного grep по подстроке.
7. **Тест ждал неверного**: при разрыве цикла родителей я ожидал обе заметки
   в корне, хотя правильное поведение (заложник остаётся под виновником) сам
   же и реализовал.
8. **Не заметил потерю заголовков** при миграции — нашёл владелец. Приёмка
   сверяла байты и структуру, но не задала вопрос «а видно ли в дереве, что
   это за заметка».

## Отложено

- Три давних красных fuzz-ops набора (класс «дословные куски не переживают
  круг правок»); лечение — «деградация тоньше», не ослабление самопроверки.
- Атомы комментариев в фаззерах (сеть свойств, плоский Backspace, уборка) —
  границы комментариев обстреляны пока только точечными тестами.
- Тонировка выделения у черты (как у картинок).
- Цветной текст — кандидат в словарь HTML.
- avif/jxl (kimageformats) — решили не тащить, webp хватает.
- `history/` создаётся, но история заметок — будущий этап; `.zametti/` пусто.
