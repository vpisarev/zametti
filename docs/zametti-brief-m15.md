# Zametti — бриф для Claude Code, этап 15: архив, бюро находок, времена

## Контекст

Скоуп сознательно урезан владельцем: цель — скорейший выход на облачную
синхронизацию, архив — её пререквизит. **Вырезано** (решения записаны,
вернёмся после синка): share-кнопка, zip-экспорт/импорт, вендоринг miniz,
даунгрейд картинок старого архива. Остались четыре вещи ниже.

Обязательное чтение: `zametti-storage.md` (корзина, шапка, времена), раздел
«Каскад картинок» отчёта 10, решения по архиву в этом брифе — финальные.

## Цель этапа

1. Корзина → **Архив**: новая иконка и семантика «тело в журнале, файл —
   стаб».
2. **Бюро находок** (lost-n-found): заметки с оборванным parent — включая
   восстановленные из системной корзины — прописываются в спецпапку.
3. **Времена → UTC с офсетом** (ISO-8601) ленивой миграцией.
4. Диалог экспорта: галочка «Сохранять имя и метаданные» с запоминанием.

`zametti-storage.md` обновляется по всем четырём пунктам — он документ
формата, а формат меняется.

## Не-цели

- share, zip в обе стороны, miniz — вырезано владельцем;
- даунгрейд/пережатие картинок архива — позже (картинки архивных заметок
  лежат как лежали);
- агрессивный дожим истории архива до одной записи — не вводится, штатное
  прореживание работает как для всех;
- поиск по телам архивных заметок: тело живёт в журнале, обычному
  Ctrl+Shift+F оно невидимо — это **названное следствие**, не баг; заголовки
  ищутся, пер-заметочный поиск истории работает;
- диалоги подтверждения — по-прежнему нигде.

## Часть 1: архив

### Архивация

Порядок жёсткий, крашеустойчивость — из него:

1. **сначала журнал**: текущее состояние сохраняется штатным путём со всеми
   правилами отбора (равно голове — записи нет; почти-дубль — замена
   последней записи, как в живом схлопывании);
2. **потом стаб**: файл заметки атомарно заменяется на шапку + строку
   заголовка (`# Название` — для списка, поиска по именам и законности
   крошечного `.md`). В шапке `role: archived`, `parent` — **оригинальный,
   не трогается** (двухпортовая механика корзины), `created`/`modified`
   сохраняются.

Падение между шагами оставляет полную заметку и запись в журнале — повторная
архивация идемпотентна; **тело потерять невозможно по построению** (инвариант
A). Вложения не трогаются вовсе: их «архивность» выводится, как выводилась
корзинность (этап 10).

### Показ и восстановление

- в дереве вместо Корзины — **Архив** (Lucide `archive`); архивные заметки
  в нём — по заголовкам стабов, обычные сортировки работают (шапка живая);
- **открытие архивной заметки = режим истории** на голове журнала: read-only
  просмотр, таймлайн, копирование — всё существующее; редактирования нет;
- **Восстановить** (кнопка «Вернуть из истории» на голове или пункт меню):
  тело из головы журнала возвращается в файл (запись `restore` штатно),
  `role: archived` снимается, заметка дома у оригинального `parent`; parent
  умер — штатная починка сирот → бюро находок. Никаких вопросов и диалогов;
- **Удалить навсегда** (контекстное меню в Архиве): бывшая «очистка корзины»
  пер-заметочно — стаб, журнал и вложения-эксклюзивы (байтовый скан этапа 10
  по остающимся заметкам) уезжают в мусорку ОС.

### Переименования

Все упоминания корзины в UI, конфиге-шаблоне и справочнике — в «Архив»;
`role: trash` в существующих файлах читается как `archived`
(псевдоним на чтении, при первом сохранении пишется новое имя — та же
ленивая миграция, что времена).

## Часть 2: бюро находок

Заметка с **неразрешимым parent** (восстановили файл из системной корзины;
скопировали из чужого хранилища руками) при загрузке и по F5/Ctrl+R
прописывается в спецпапку «Бюро находок»:

- **первое санкционированное исключение из правила «загрузка не пишет»**,
  рамки жёсткие: только заметки с неразрешимым parent; запись строго
  «текущий порт := бюро, оригинал := сохранён» (двухпортовая механика
  корзины/архива); идемпотентно — уже прописанные не трогаются; атомарно,
  штатным путём сохранения (журнал получает запись обычным порядком);
  **`modified` не поднимается** — организационная правка;
- бюро — спецпапка в дереве (иконка на вкус исполнителя из Lucide, снимок
  покажет), видна только когда непуста;
- вытаскивание — обычный перенос в любую папку; сама папка ничем больше не
  управляет;
- id-коллизии между хранилищами объявлены владельцем пренебрежимыми — никакой
  машинерии, одна фраза в справочнике формата.

## Часть 3: времена — UTC с офсетом

`created`/`modified` в шапках переходят на **ISO-8601 с офсетом**
(`2026-08-14T21:40:00+02:00`): и абсолютный момент, и локальный контекст в
одной строке.

- **чтение — оба формата**: старые метки без офсета интерпретируются в
  локальной зоне читающей машины (допущение задокументировать в
  справочнике);
- **запись — ленивая миграция**: любое сохранение заметки пишет оба поля в
  новом формате (значения сохраняются, конвертируется представление);
  специального прохода по хранилищу нет;
- **все сравнения и сортировки — по UTC-инстантам**: сортировка «по дате
  создания» этапа 14 обязана давать одинаковый порядок в любой зоне;
- журнал не трогается — он в UTC-миллисекундах с этапа 7;
- показ дат в UI — в локальной зоне читателя, форматы как были.

## Часть 4: галочка экспорта

В диалоге экспорта `.md` — галочка **«Сохранять имя и метаданные»**,
состояние запоминается в `state.json`:

- **выключена** (дефолт, как сейчас): имя из заголовка, шапка срезана;
- **включена**: файл `<id>.md`, шапка как есть — на принимающей стороне
  zametti такой файл после копирования в хранилище попадает в бюро находок
  (parent оборван) — обмен заметками работает без share-механики;
- вложения в обоих режимах — как сейчас (id-именами рядом).

## Инварианты и тесты

```
A. Архивация не теряет ни байта тела: журнал получает состояние ДО среза;
   падение между шагами оставляет полную заметку; повтор идемпотентен
B. Восстановление возвращает тело головы и оригинальный parent (мёртвый
   parent → бюро находок)
C. Загрузка и F5 идемпотентны: второй проход не пишет ничего
D. Порядок сравнения времён инвариантен к зоне машины
```

- архивация: обычная заметка, только-что-сохранённая (записи нет — голова
  равна), почти-дубль (замена последней), повтор; стаб парсится ядром;
- восстановление: домой, в бюро (parent умер), Ctrl+Z после восстановления;
- удалить навсегда: каскад с общей картинкой (остаётся) и эксклюзивной
  (уезжает), журнал уезжает вместе;
- `role: trash` старых файлов читается как архив, переписывается при первом
  сохранении;
- бюро: «восстановленный из системной корзины» (фикстура: файл с parent,
  которого нет), чужая копия, два порта, идемпотентность, перенос наружу,
  `modified` не тронут;
- времена: round-trip обоих форматов; фикстура «Китай→Москва» — правки в
  +08:00, чтение и сортировка в +03:00, порядок по created/modified верен;
  смешанное хранилище (старые и новые метки) сортируется правильно;
- галочка: оба режима экспорта, состояние переживает перезапуск;
- `zametti-storage.md`: разделы «Архив», «Бюро находок», «Времена», экспорт —
  обновлены (проверка глазами);
- Xvfb-снимки: Архив в дереве с заметками, открытая архивная (режим
  истории), бюро находок с находкой.

Критерий глазами: заархивировать заметку с фотками — файл превратился в
стаб, фотки на месте; открыть из Архива — история, утащить абзац; вернуть —
дома, как была; выкинуть файл заметки в системную корзину, восстановить
оттуда, F5 — она в бюро находок; экспортировать с галочкой, скопировать в
копию хранилища — там она в бюро; выключить галочку — обычный красивый
экспорт.

## Правила работы

- Ничего за пределами репозитория; хранилище владельца — только чтение;
  тип сборки и файлы владельца оставлять как нашёл.
- Широкое окно в матрице UI-тестов; Debug и Release; снимки Xvfb как
  артефакт приёмки.
- Каждая починка проверяется снятием — целиком; матрицы краёв до починок.
- «Мои ошибки» обязательны. Измерять, а не рассуждать; сомнение — спросить.
