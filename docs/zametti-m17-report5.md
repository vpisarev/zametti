# Этап 17, сессия 5: диалог хранилищ, список в state.json, сброс пароля

27.08.2026, ветка `main`. Задача сессии — UI настройки и сброса облачной
синхронизации; по ходу обсуждения владелец переопределил интерфейс, и итог
шире исходной задачи-минимум.

## Решения владельца, принятые в этой сессии

- **Кнопка database — вход в диалог управления хранилищами.** Список
  известных хранилищ устройства, «+» / «−», переключение; у каждого —
  опциональное облако (url + логин + пароли) и своя локальная папка.
  Прежний голый выбор каталога живёт внутри диалога (Browse).
- **Кнопка sync отвечает только за синк.** Не настроен — погашена, подсказка
  отсылает к диалогу хранилищ.
- **Список хранилищ загружается в ядре** и лежит в state.json: «state.json
  должен хранить не только путь к текущему активному storage, но и отдельно
  список папок — иначе остальные хранилища не найти». Всякое успешно
  открытое хранилище попадает в список само; «−» лишь забывает строку.
- **Одна структура, а не две**: прежний `ZStorage::RemoteConfig` слит в
  `ZStorage::Config` («слишком много структур и так»), поля локальной и
  облачной сторон различимы именами (`root` против `remoteUrl`/`remoteDir`/
  `remoteUser`) — просьба владельца об аккуратном, а не механическом
  рефакторинге.
- **Сброс пароля шифрования — с переспросом** (названное владельцем
  исключение из «никаких диалогов», как «удалить насовсем» у Архива) и
  двойным вводом нового пароля; живёт в форме хранилища.

## Сделано

### Ядро

- **`ZStorage::probeCloud`** (static) — разведка адреса ДО выбора локальной
  папки: листинг (он же проверка адреса и пароля сервера), манифест, конверт
  и его разворот криптопаролем, имя облака best-effort, счёт журналов и
  объёма по открытым именам — ноль расшифровок содержимого.
- **`ZStorage::resetCloudEncryption`** — единственная стирающая операция над
  облаком (случай «пароль забыт»: конверт без пароля не развернуть по
  построению). Чужой или нечитаемый манифест — отказ; новый keyfile чеканится
  до первой стирающей операции; чистка идёт конвертом и манифестом вперёд
  (оборванная не выглядит целым хранилищем); затем `pushAll` заново; леджер
  синка сбрасывается. Обрыв в любой точке долечивается следующим прогоном:
  облако без манифеста — «первый синк».
- **`ZStorage::Config`** — слияние с `RemoteConfig`: одна запись на
  хранилище. В `remote.json` уходит только облачная сторона
  (`remoteBytes()`: путь, вписанный в файл, протух бы при `cp -r`), строка
  списка (`entryJson()`) несёт всё. Читатель один и понимает прежние ключи
  `url`/`dir`/`user` запасным путём — старые remote.json читаются и мигрируют
  при следующей записи. `isEmpty()` с двумя смыслами не живёт: «облако
  настроено?» — явный `hasCloud()`, каждое прежнее место осмыслено заново
  (LSP findReferences, без sed). `remoteConfig()` заполняет `root` корнем
  копии — ПОСЛЕ разбора (читатель пишет все поля).
- **`ZAppState::stores`** — список хранилищ устройства в state.json
  (`rememberStore` / `forgetStore` / `storeFor`): канонизация корня,
  дедупликация, обновление знакомой строки НА МЕСТЕ (порядок стабилен —
  список в диалоге не прыгает), пустое имя прежнего не затирает. Чтение идёт
  через тот же `rememberStore`. `localStoreName()` открыт (имя строки).

### Приложение

- **`StoreManagerDialog`** (`app/store_manager_dialog.{h,cpp}`) — слева
  список, справа форма строки. Ветки решает состояние папки и облака, и все
  они в ядре: подключение/чеканка (свежее облако — пароль дважды: опечатка
  запечатала бы его навсегда), неразрушительное обновление адреса ключом из
  keyring, отвязка (аналог CLI `--reset`, секреты чистятся), `probeCloud` до
  скачивания → `initFromRemote`, засев пустой папки с переспросом (второе
  исключение), сброс пароля. Сеть и Argon2id — в рабочем потоке (окно живёт,
  форма глохнет, занятый диалог не закрывается); keyring — только из
  главного потока: рабочему отдаётся копилка `TakenSecrets`, добытое
  перекладывается по завершении. Чужие корни открываются временным
  `ZStorage` под замком; «−» у открытого хранилища погашен (строка вернулась
  бы при следующем прицеплении).
- **Проводка** (`main.cpp`): `manageStores` вместо `chooseStore`; прогон
  синка останавливается и дожидается до диалога; список применяется всегда
  (и по Esc); после скачивания первый прогон запускается независимо от
  `sync.onStart` — в папке пока только манифест и корень. `attachStore`
  кладёт открытое хранилище в список — это же бесплатная миграция прежнего
  `storeRoot`. `syncSecrets` явный и один на контроллер и диалог.

## Живая приёмка (Xvfb, широкое окно 1600×900, песочница ZAMETTI_CONFIG_DIR)

1. Свежее хранилище `--root` → строка легла в список с именем; заметка
   создана, окно живое (снимок).
2. Переключение на копию vpnotes на ходу (`ZAMETTI_PROBE_STORE` — тот же
   `attachStore`, что зовёт Open диалога): прицепилось, замок прежнего
   отпущен, в списке две строки с именами (снимок).
3. Перезапуск без аргументов: открылось последнее, список цел.

## Мои ошибки

- **Наступил на документированную ловушку WAYLAND_DISPLAY под Xvfb** (она
  записана в памяти проекта с этапа 9 — не перечитал). Три «Xvfb»-прогона
  открыли окно на живом экране владельца, и его клавиши («ук») напечатались
  в заметку ПЕСОЧНИЧНОГО хранилища. Данные владельца не тронуты, но урок
  жёсткий: всякий GUI-прогон — только `env -u WAYLAND_DISPLAY` +
  `QT_QPA_PLATFORM=xcb`. Нашёл по «заметка сама набрала текст» и
  невоспроизводимости.
- **`TestData::outDir` чистит каталог при каждом вызове** — второй снимок
  приёмки молча стёр первый. Каталог теперь берётся один раз на набор.
- **`Config::parse` затирал `root`, поставленный до разбора** (читатель
  пишет все поля, а в remote.json корня нет). Поймано чтением кода при
  правке `remoteConfig()`; порядок — сперва разбор, потом корень.
- **Проверка свежести облака зацикливалась**: «конверта нет» → показать
  повтор пароля → повторное нажатие снова спрашивало свежесть. Поймано
  проглядкой веток до прогона; введён явный флаг «свежесть выяснена»,
  который забывается при правке адреса.
- В набор сперва позвал protected `MiniStore::write` — увидел по
  диагностике, записал файл напрямую.
