# Zametti — бриф №18: книги (fb2), замок, режим чтения, аннотации, букмарки

Статус: **черновик на ревью владельца**. Решения из дизайн-сессии 05.09.2026 —
финальные; мои дополнения помечены `[VETO?]`. Бриф рассчитан на **две сессии**
(18a и 18b, границы в разделе «Порядок работы»), с отчётом и `/clear` между ними.

## Цель

Складировать и читать в Zametti книги: фантастику, классику, open-source
учебники и лонгриды. Для этого: импорт fb2 → markdown, книжные метаданные,
защита заметки от случайной правки, режим чтения, активное чтение
(выделения, комментарии, букмарки) поверх защищённого текста.

## Контекст (на что опираться, ничего не дублировать)

- Хранилище: плоские `<id>.md` + вложения `<id>.<ext>` + `history/<id>.log`.
  Метаданные заметки — в существующем заголовке (`role:` уже есть, архив
  read-only уже реализован). Новые поля добавляются в **тот же** формат.
- Рендер: единый конвейер ZDocument → view, RenderStyle. Режим чтения — это
  **другой RenderStyle + другая политика взаимодействия**, а не второй виджет и
  не второй путь рендера (CLAUDE.md: без путей-двойников, кэш встроен в
  конвейер).
- Импорт .md через контекстное меню уже есть (источник не трогается,
  канонизация, времена из заголовка/fs). Импорт fb2 идёт **тем же путём**,
  добавляется только конвертер.
- Вложения: существующий путь сохранения (BLAKE3, дедуп, decode). Картинки из
  fb2 идут через него.
- Синк (бриф №17): dirty-set, любое изменение `.md` — обычная грязная заметка.
  Никакой специальной обработки для аннотаций/букмарков.
- F4/Ctrl+]/Ctrl+[ заняты навигацией по `+++/---` в просмотре истории.
  В режиме чтения Ctrl+]/[ перекрываются; F4 и просмотр истории не трогаем.
- Проверено владельцем: «Братья Карамазовы» (350 000+ слов) грузятся,
  рендерятся и редактируются шустро. Разбиение книг по главам **не нужно**,
  одна заметка = одна книга.

## Принятые решения (не пересматривать в сессии)

1. **Режим чтения — состояние вида, доступное для любой заметки.** `role: book`
   даёт только дефолты (открывать в чтении, книжная карточка в списке, схема
   метаданных).
2. **Замок — флаг `readonly` в заголовке, отдельно от роли.** Read-only —
   ограничение *редактора*, а не файла: аннотации пишутся в тот же `.md`.
   Sidecar-файлов для аннотаций нет.
3. **Авторские примечания = markdown footnotes** `[^id]` (в fb2 это
   `<body name="notes">`). **Собственные комментарии = CriticMarkup**
   `{>>текст<<}`. Выделения = `==текст==`. Три разных конструкции, коллизий нет.
4. **Букмарки — вне текста**, список в заголовке заметки, якорь по фрагменту
   текста (не по номеру строки). **Позиция чтения — локальное состояние**, не в
   файле, не в синке. Правило: явные действия пользователя → в файл, неявное
   состояние → локально.
5. Временная разблокировка (для правки опечатки) — в памяти, флаг в файле не
   трогает, сбрасывается при уходе с заметки.

## Спецификация

### 1. Метаданные

Новые поля заголовка (все опциональны, кроме тех, что ставит импорт):

| поле | тип | источник fb2 |
|---|---|---|
| `role: book` | — | импорт |
| `readonly: true` | bool | импорт / замок |
| `author` | строка или список | `title-info/author` («Имя Фамилия»; несколько → список) |
| `translator` | строка/список | `title-info/translator` |
| `year` | число | `publish-info/year`, иначе `title-info/date@value` (год) |
| `isbn` | строка | `publish-info/isbn` |
| `publisher` | строка | `publish-info/publisher` (+ `city` через запятую) |
| `series` | строка | `title-info/sequence` → «Название #N» |
| `lang` | строка | `title-info/lang` |
| `genre` | список | `title-info/genre` |
| `cover` | id вложения | `coverpage/image` |
| `source` | строка | `имя-файла.fb2` + BLAKE3 исходника |
| `bookmarks` | список записей | см. §7 |

Заголовок заметки = `book-title`. Аннотация книги (`title-info/annotation`) —
в тело, первым блоком, как цитата `> …` `[VETO?]` (в заголовке длинному тексту
не место). Остальное из `description` отбрасывается; словарь `extra` **не**
заводим `[VETO?]` — схема минимальна, расширим когда понадобится.

Список заметок для `role: book`: вместо превью текста — автор · год `[VETO?]`.

### 2. Импорт fb2

Точка входа — тот же контекстный «Импорт…», что для `.md`, с фильтром
`*.fb2`. `.fb2.zip` — **не в этой сессии** (в Qt нет zip; владелец распакует).

Парсер: `QXmlStreamReader`, namespace `http://www.gribuser.ru/xml/fictionbook/2.0`,
ссылки `l:href` (xlink). **Кодировка**: старые fb2 часто в `windows-1251` —
проверить, что `QXmlStreamReader` в нашей сборке Qt6 её декодирует; если нет —
таблица cp1251→UTF-8 на 128 записей перед парсингом, без внешних зависимостей.
Это первое, что надо проверить на реальных файлах.

Отображение элементов:

| fb2 | markdown |
|---|---|
| `body` (главное тело) | текст заметки |
| `body[name=notes]` | footnotes: `<section id="X">` → `[^X]: текст`; многоабзацные — с отступом продолжения |
| `body[name=comments]` и прочие | как notes `[VETO?]` |
| `section` глубины d (1 = верхний) | `title` → заголовок `#`×(d+1), не глубже `######`; без `title` → `---` `[VETO?]` |
| `title` из нескольких `<p>` | склейка через « · » `[VETO?]` |
| `p` | абзац |
| `subtitle` | абзац `**жирным**` |
| `empty-line` | пустая строка |
| `epigraph` | цитата `> *курсивом*`; `text-author` → строка `> — Автор` |
| `cite` | цитата `> …`; `text-author` → `> — Автор` |
| `poem` / `stanza` / `v` | цитата; строки с жёстким переносом (в принятой у нас нотации), строфы через пустую строку; `title` строфы — жирным; `text-author` → `— Автор` |
| `emphasis` / `strong` / `strikethrough` | `*…*` / `**…**` / `~~…~~` |
| `sub` / `sup` | `<sub>` / `<sup>` |
| `code` | `` `…` `` |
| `a[type=note]` | `[^X]` (X = id из href без `#`) |
| `a` прочие | `[текст](href)`; внутренние `#id` — оставить как текст (локальные ссылки пока не поддерживаем) |
| `image` (блок и inline) | `![](вложение)`; `binary` → base64 → существующий путь сохранения вложений |
| `table` | markdown-таблица; при colspan/rowspan — уплощить |
| `coverpage/image` | вложение + поле `cover`; в тело **не** вставлять `[VETO?]` |

Санитизация: id примечаний — только `[A-Za-z0-9_-]`, иначе перенумеровать
`n1, n2…` с сохранением соответствия. Если наш footnote-парсер требует чисто
числовых меток — перенумеровать всегда (проверить). Пробелы внутри `<p>`
нормализовать.

После импорта: `role: book`, `readonly: true`, заметка открывается в режиме
чтения. Повторный импорт того же файла → новая заметка (как у `.md`), никакого
«обновления поверх».

### 3. Замок

`effective_readonly = (readonly && !temp_unlocked) || role == archive`.

Тулбар: иконка `lucide:lock` / `lucide:lock-open`; временная разблокировка —
`lock-open` с акцентным цветом `[VETO?]`. Для `archive` — `lock`, disabled
(разблокировка архива — существующий путь разархивирования).

- Клик по открытому → сразу `readonly: true`, без диалога.
- Клик по закрытому → диалог с тремя кнопками: **«Разрешить правку до
  переключения заметки»** (temp_unlocked в памяти, по id; сбрасывается при
  переключении заметки, закрытии окна, повторном открытии), **«Снять
  защиту»** (удалить флаг из файла), «Отмена».
- Клик по временно открытому → закрыть обратно, без диалога.

В запертом состоянии заблокированы: ввод, paste, drop, drag, undo/redo текста,
прямой режим правки `.md` (открывается как read-only). Реализация — на уровне
редактора (`setReadOnly(true)` блокирует пользовательский ввод, программные
вставки через курсор работают — этим и пользуются аннотации).

**Разрешены** в запертом состоянии: выделение текста, копирование, все
операции аннотирования (§5) и букмарки (§7). Эти правки идут через обычный
путь сохранения и журнал истории — как любая правка.

### 4. Режим чтения

Тулбар: `lucide:book-open-text`, toggle. Shortcut — открытый вопрос.

Внешний вид — отдельная группа настроек «Чтение»: шрифт (по умолчанию
системный serif), кегль, интерлиньяж (1.5), ширина колонки (~34 em),
поля. Реализуется как второй RenderStyle; **не** копировать конвейер.
Первая строка абзаца с отступом вместо пустой строки между абзацами —
`[VETO?]`, если дёшево.

Взаимодействие:
- Текстовый ввод отключён всегда, независимо от замка (правка опечатки =
  выйти из режима чтения + отпереть) `[VETO?]`. Выделение и копирование
  работают. Аннотации и букмарки работают.
- Листание: `Space`/`PgDn`/`→` — вперёд, `Shift+Space`/`PgUp`/`←` — назад,
  `Home`/`End`. Страница = высота viewport минус одна строка перекрытия,
  выровнено по верху строки. Честной пагинации нет.
- Footnotes: клик по `[^X]` — popup с текстом примечания; рендер в конце
  документа сохраняется.
- Зум — существующий путь.
- Панели/тулбар не прячем (фокус-режим — не-цель).

По умолчанию: `role: book` → режим чтения, остальные → редактор; последний
выбранный режим запоминается в локальном состоянии (§8).

### 5. Аннотации

**Выделение** `==текст==`. Проверить, что уже парсится и рендерится; если
нет — добавить (фон жёлтый). Команда «Выделить» (`Ctrl+Shift+H` `[VETO?]`):
toggle вокруг выделенного текста; выделение через несколько блоков → по
одному `==…==` на блок; если весь фрагмент уже выделен → снять. Внутри
кода/математики `==` — литерал.

**Комментарий** `{>>текст<<}` — единственная конструкция CriticMarkup,
которую парсим; `{++…++}`, `{--…--}`, `{==…==}` — не-цель. Текст комментария —
одна строка, без `<<}` внутри. Рендер — inline-пузырёк с отличным от
выделения фоном (голубой) `[VETO?]`; работает на узком экране, поэтому
инлайн, а не поля.

Команда «Комментарий» (`Ctrl+Shift+M` `[VETO?]`): вставляет `{>><<}` сразу
после выделения (после закрывающих `==`, если фрагмент выделен) или в позицию
курсора, и открывает **popup-редактор** текста комментария. Popup, а не
правка внутри документа: так не нужно учить запертый редактор «пускать ввод
только между скобками». Клик по пузырьку → тот же popup (правка/удалить);
пустой текст → конструкция удаляется.

**Скрыть/показать комментарии** (`Ctrl+Shift+K` `[VETO?]`): глобальная
настройка, persist. В скрытом состоянии `{>>…<<}` не рендерится вовсе;
выделения и букмарки не затрагиваются; команда «Комментарий» снимает
скрытие.

В прямом режиме правки `.md` все маркеры видны как есть. Поиск находит текст
комментариев (это обычный текст).

### 6. Навигация Ctrl+] / Ctrl+[

Только в режиме чтения: следующая/предыдущая **пометка** в порядке документа —
начало `==…==`, `{>>…<<}` или букмарк — относительно курсора (если есть) или
верха viewport. Без зацикливания; в конце — сообщение в статусной строке
`[VETO?]`. Вне режима чтения Ctrl+]/[ и F4 работают как раньше.

### 7. Букмарки

Запись в заголовке заметки, список `bookmarks`, в существующем формате
заголовка; поля записи:

```
snippet:  первые 40 символов абзаца (plain text без разметки, пробелы нормализованы)
heading:  путь по заголовкам, «Книга первая / III. Второй брак»
line:     строка источника на момент создания (подсказка, не якорь)
name:     необязательное имя
created:  время
```

- `Ctrl+Shift+B` — toggle на текущем абзаце (абзац с курсором; в чтении без
  курсора — первый полностью видимый). Повторно → снять.
- На полях — `lucide:bookmark` у абзаца; клик → снять `[VETO?]`.
- Список букмарков (popup из иконки на тулбаре `[VETO?]`): snippet (или
  `name`), заголовок; клик → переход; правка имени; удаление. Потерянные — серым,
  с пометкой «не найдена», можно только удалить.

**Разрешение якоря** при открытии заметки: точное совпадение `snippet` по
блокам → если несколько, ближайший к `line` → иначе fuzzy (нормализованное
расстояние ≤ порога, **порог после замера** на реальных правках, не до) в
пределах `heading` → иначе потеряна. В сессии букмарк привязан к блоку
(userData/позиция), переживает правки без переразрешения. При сохранении
`snippet`/`line`/`heading` **перезаписываются** из текущего блока —
самовосстановление якорей `[VETO?]`.

Синк: правка заголовка = обычная правка заметки.

### 8. Локальное состояние (не в файле, не в синке)

`reading-state.json` в каталоге данных приложения, ключ `storeId/noteId`:
`mode` (чтение/редактор), `pos` — индекс первого видимого блока + доля
внутри блока (не пиксели: устойчиво к зуму и смене шрифта), `updated`.
Запись с debounce ~1 с после остановки прокрутки, при переключении заметки
и при выходе. Рост файла: одна запись на заметку, чистить записи для
несуществующих заметок при старте.

### 9. Матрица взаимодействий

| операция | редактор, открыто | редактор, заперто/temp | чтение (любой замок) | архив |
|---|---|---|---|---|
| ввод/paste/drop | да | нет (temp: да) | нет | нет |
| выделить / комментарий | да | да | да | да `[VETO?]` |
| букмарк | да | да | да | да |
| Ctrl+]/[ | история | история | пометки | история |
| Space/PgDn | ввод/скролл | скролл | листание | скролл |
| прямая правка .md | да | read-only | read-only | read-only |

`[VETO?]` аннотации в архиве: логично (архив читают), но архив — стаб + тело
в журнале, правка меняет стаб. Если это ломает инвариант архива — запретить,
не ломая архив.

## Порядок работы

**Сессия 18a**: §1 метаданные → §2 импорт fb2 (сначала кодировка и notes на
реальном файле, потом остальная таблица) → §3 замок → §9 матрица в
сравнении с реализацией → отчёт → `/clear`.

**Сессия 18b**: §4 режим чтения → §5 аннотации → §6 навигация → §7 букмарки →
§8 локальное состояние → отчёт.

Перед кодом каждого раздела — матрица взаимодействий с существующими
режимами (CLAUDE.md). Пороги (fuzzy, debounce) — только после замера.

## Не-цели

- epub/html/`.fb2.zip` импорт, экспорт обратно в fb2.
- Sidecar-файлы аннотаций, обновление книги поверх старого импорта.
- Синк позиции чтения между устройствами.
- Честная пагинация, фокус-режим, скрытие панелей.
- Остальной CriticMarkup, вложенные/многострочные комментарии.
- Внутренние ссылки `#id` по книге, оглавление как отдельная панель.
- Разбиение книг по главам.

## Тесты и приёмка

- **Корпус fb2**: «Братья Карамазовы» + маленький рукописный fb2, покрывающий
  всю таблицу §2 (вложенные секции, поэма, цитата, эпиграф, примечания в т.ч.
  многоабзацные, картинки, таблица, `windows-1251`). Golden markdown в
  репозитории; импорт дважды → идентичный текст (id/времена вне сравнения).
- Примечания: каждая `a[type=note]` в источнике → ровно один `[^X]` с
  соответствующим `[^X]:`; сироты — ошибка теста.
- Замок: ввод/paste игнорируются; аннотация проходит; temp сбрасывается при
  переключении; «снять защиту» пишет заголовок.
- Аннотации: toggle туда-обратно = исходный текст; разбиение по блокам;
  комментарий добавить/править/удалить; скрытие; `==`/`{>>` в коде — литерал.
- Навигация: порядок пометок совпадает с порядком в документе.
- Букмарки: создать → сохранить → открыть → найдена; вставка текста выше →
  найдена; правка внутри snippet → fuzzy; удаление абзаца → потеряна;
  самовосстановление перезаписало `line`.
- **Замеры (в отчёт, без порогов заранее)**: время импорта Карамазовых, время
  открытия в режиме чтения, время разрешения N букмарков.
- Ручной прогон синка: аннотация на A → синк → видна на B.

## Открытые вопросы (владельцу, до/во время 18b)

1. Shortcuts: выделить/комментарий/скрыть (`Ctrl+Shift+H/M/K` — проверить
   конфликты с существующими), shortcut режима чтения.
2. Комментарии: inline-пузырёк или заметки на полях (в 18b, по факту рендера).
3. Аннотация книги — в тело как цитата или в заголовок.
4. Аннотации в архивных заметках — разрешить или нет.
5. Нужны ли букмаркам имена, или достаточно snippet.
