# Zametti — бриф для Claude Code, этап 3: плоское хранилище и id

## Контекст

Этапы 1–2 закрыты: ядро `markdown → IR → markdown` с инвариантами идемпотентности
и WYSIWYG-редактор с моделью по осям (`Kind` + `Marker` + `level`, `VSpace`-блоки).
Обязательное чтение перед началом: `zametti-brief-m1.md`, `zametti-brief-m2.md`,
`zametti-core-notes.md`, `zametti-editor-notes.md`, `zametti-m1-report.md`,
`zametti-m2-report-1.md` — зафиксированные там решения здесь не повторяются.

Этот этап переводит хранилище на финальное представление: **плоский каталог
заметок с непрозрачными id вместо путей и имён**. Поиск, картинки, история и
синхронизация в следующих этапах строятся уже поверх него.

Красный фаззер этапа 2 (класс «дословные куски не переживают круг правок») этот
этап не блокирует и в нём не чинится: миграция использует только parse/serialize,
которые на реальных файлах зелёные.

## Цель этапа

1. Формат хранилища: `<id>.md` плоско, метаданные в HTML-комментарии, иерархия
   через `parent`.
2. Слой метаданных в ядре + пакет канона: `Kind::Divider`, image-спан.
3. Приложение работает с плоским хранилищем: дерево из метаданных, создание /
   переименование / перенос / удаление заметок как правка метаданных.
4. Консольная утилита: создание пустого хранилища, импорт дерева `.md`,
   обогащение метаданными из Apple Notes, верификация.

## Не-цели

- поиск и индекс; пережатие картинок (WebP, классификатор lossless/lossy) и
  конвейер вставки — перенос уже существующих вложений при импорте при этом
  **входит** в этап, см. `import`;
- журнал истории, шифрование, синхронизация, Android;
- правки движка редактирования (красный фаззер, инлайновый rawSource — отложены);
- совместимость с Obsidian/front matter;
- извлечение данных из Apple Notes на маке (JXA-скрипт — отдельная работа;
  здесь — только потребление его выходного формата).

Не-цели — это не пожелания. Кажется, что без чего-то не обойтись, — остановиться
и спросить.

## Формат хранилища

### Файлы

Корень хранилища — плоский каталог: `<id>.md` для каждой заметки, ничего больше.
Служебное — только в зарезервированных именах: `.zametti/` (состояние, в этом
этапе может быть пустым) и `attachments/` — плоский каталог вложений. Имя
вложения — первые 32 hex-символа sha256 содержимого + родное расширение:
дедупликация и проверка целостности бесплатно. Никаких подкаталогов с заметками.

### Id

- 14 символов, Crockford base32 в нижнем регистре: алфавит `0-9` + `a-z` без
  `i l o u`. Валидация: `^[0-9a-hjkmnp-tv-z]{14}$`.
- Структура: 8 символов — unix-секунды создания заметки, big-endian, с ведущими
  нулями; 6 символов — случайные (CSPRNG).
- Создание файла — `O_EXCL`; при `EEXIST` перегенерировать случайную часть.
- Ближайшее тысячелетие все id начинаются с `0` — это ожидаемо и служит
  де-факто признаком формата.
- **В логике id непрозрачен**: время из него не разбирается никогда; настоящая
  дата создания живёт в метаданных. Временной префикс — только для сортировки
  `ls` и глаз при отладке.

### Метаданные

Первый блок файла — HTML-комментарий фиксированной формы:

```
<!-- zametti
parent: 01n6x9k2m4qp
created: 2019-03-14T09:26:53Z
modified: 2026-07-29T21:40:00Z
tags: дом, море
-->

# Заголовок заметки
```

Правила:

- Первая строка — ровно `<!-- zametti`, дальше строки `key: value`, закрывающая
  `-->` отдельной строкой. После блока — пустая строка (`VSpace`), затем контент.
- Известные ключи: `parent` (id; отсутствует ⇒ заметка в корне), `created`,
  `modified` (ISO-8601 UTC, `YYYY-MM-DDTHH:MM:SSZ`), `tags` (через запятую,
  пробелы в теге допустимы, запятая — нет).
- **Неизвестные ключи сохраняются дословно и в своём порядке** — это forward
  compatibility, обязательный тест на побайтовый round-trip.
- Значения не содержат `--` (ломает HTML-комментарий); id и ISO-даты безопасны
  по построению, теги валидируются при записи.
- **Id заметки нигде не дублируется внутри файла** — он только в имени. Один
  источник истины, рассинхрону неоткуда взяться.
- `modified` обновляется приложением при сохранении. Так как сохранение
  происходит только при реальном изменении содержимого (правило хеша из этапа
  2), цикла «сохранение ради metadata» не возникает. Внешние правки оставляют
  `modified` устаревшим — это принято; mtime остаётся подсказкой.

### Слой метаданных в ядре

md4c отдаёт комментарий обычным HTML-блоком — препроцессора не нужно. Ядро
после разбора распознаёт первый блок с маркером `zametti`, поднимает его в
`Document::meta` и убирает из списка блоков; сериализация выводит метаданные
первым блоком обратно. Редактор метаданные **не видит вообще** — в
`QTextDocument` они не попадают, курсору встать некуда.

Комментарий без маркера `zametti` (просто чей-то HTML-комментарий первым
блоком) метаданными не является и остаётся обычным `rawSource`-блоком.

### Иерархия

- **Каталог — это обычная заметка, у которой есть дети.** Отдельного рода,
  флага или сущности нет. Пустая заметка с одним заголовком — типичная «папка»;
  заметка с текстом и детьми тоже легальна.
- Дерево строится одним проходом: скан всех `<id>.md`, чтение метаданных и
  заголовка.
- **Заголовок** = текст первого `Heading`-блока файла (любого уровня); если
  первый содержательный блок не заголовок — первая непустая строка текста,
  усечённая; совсем пустая заметка — подпись «Без названия».
- Починка структуры при загрузке: `parent`, указывающий на несуществующий id, —
  заметка показывается в корне с пометкой; цикл родителей — рвётся, виновник в
  корень с пометкой. **Загрузчик никогда не переписывает файлы** — починка
  живёт в памяти и в логе, исправление делает пользователь переносом заметки.

## Пакет канона (замораживается этим этапом)

Миграция нормализует весь корпус — это единственный момент, когда канон меняется
дёшево. Вместе с метаданными в канон входят:

- **`Kind::Divider`** — тематический разрыв; канонический вывод `___`
  (подчёркивание — единственный из трёх символов, не конфликтующий ни с
  setext-заголовками, ни с буллетами списков, ни с front-matter-забором чужих
  инструментов); вход `---`/`***`/варианты с пробелами приводится. Внимание:
  `Foo` + `---` следующей строкой — это setext-заголовок по спецификации, а не
  разделитель; он остаётся заголовком (и уходит в ATX по канону этапа 1).
- **Image-спан**: `![alt](путь)` и `![alt](путь "title")` — парсинг, побайтовая
  сериализация, отображение локальных существующих файлов в просмотре
  (масштаб по ширине колонки, HiDPI через devicePixelRatio). Фрагмент в URL
  (`#w=…` и прочее) сохраняется байтами, но в этом этапе не интерпретируется.
  Вставка, пережатие, вложения — не в этом этапе.
- Всё остальное непредставимое остаётся `rawSource` как есть.

После этого корпусная метрика дрейфа (`сколько файлов меняется от
serialize(parse(x))`) обязана стать нулевой на мигрированном хранилище и войти
в тесты как ноль.

## Приложение

- `zametti --root <path>`; последний корень запоминается в состоянии
  (`.zametti/state.json` или существующий механизм сеанса — согласовать с тем,
  что уже есть).
- Дерево: показывает заголовки; **заметки-каталоги** раскрываются. Сортировка
  по умолчанию: каталоги первыми по алфавиту, затем заметки по `modified`,
  свежие сверху (поведение Apple Notes); ключ сортировки — параметр конфига.
- **Автообновление узла дерева**: правка первого заголовка заметки обновляет
  подпись узла при сохранении (не на каждый символ).
- Операции (каждая — правка метаданных или текста, файлы не переименовываются
  и не перемещаются никогда):
  - `Ctrl+N` — новая заметка: id от текущего времени, `parent` — выбранный
    каталог (или корень), `created` = `modified` = сейчас, тело — пустой
    заголовок `# `, курсор в нём;
  - «Новый каталог» — то же самое, просто пользователь ожидает детей;
  - перенос заметки в другой каталог (drag&drop в дереве и/или контекстное
    меню) — правка одной строки `parent` у переносимой; перенос каталога
    переносит его поддерево автоматически, потому что дети ссылаются на него;
    запрет: нельзя переносить каталог внутрь собственного поддерева;
  - удаление одной заметки — через системную корзину (`QFile::moveToTrash`),
    с подтверждением, если у заметки есть дети (дети становятся сиротами и
    всплывут в корне с пометкой — это осознанно, каскадного удаления нет);
  - переименование — это просто правка заголовка в тексте; отдельной команды
    не нужно, но F2 в дереве может ставить курсор в заголовок.
- Теги: разбираются в `Document::meta`, доступны модели дерева (тултип узла);
  никакого UI фильтрации в этом этапе.

## Утилита `zametti-store`

Консольный бинарник на ядре, без GUI. Подкоманды:

### `init <dir>`
Создаёт пустое хранилище: каталог, `.zametti/`, проверка прав. Отказывается
работать в непустом каталоге.

### `new --root <dir> [--parent <id>]`
Создаёт пустую заметку с корректным id, печатает путь. Для скриптов.

### `import --root <dir> --from <srcdir> [--apple-manifest <json>] [--dry-run]`

Импорт дерева `.md`-файлов:

- каждый подкаталог источника → заметка-каталог (заголовок — имя каталога);
  каждый `.md` → заметка; иерархия воспроизводится через `parent`;
- содержимое прогоняется через parse/serialize ядра — импорт и есть
  нормализация;
- времена: приоритет — manifest Apple Notes (см. ниже), иначе front matter
  источника, если есть, иначе fs-времена файла с пометкой в отчёте;
  `created` кодируется в id;
- **вложения**: файлы, на которые указывают локальные `![...]`-ссылки
  импортируемых заметок, копируются в `attachments/` под хеш-именами **байты в
  байты, без пережатия** (конверсия в WebP — отдельный проход будущего этапа);
  одинаковое содержимое ложится в один файл; ссылки в заметках переписываются
  на `attachments/<hash>.<ext>`; отсутствующая цель ссылки — в отчёт, ссылка
  остаётся как есть; сводка по форматам и размерам вложений — в отчёт (по ней
  будет настраиваться пережатие);
- **относительные ссылки** на `.md` внутри импортируемого набора
  переписываются на `<id>.md`; не разрешившиеся — остаются как есть и попадают
  в отчёт; `[[wikilinks]]` не переписываются — только считаются и
  отчитываются;
- имена исходных файлов записываются в отчёт соответствия
  (`старый путь → id`), сам отчёт кладётся рядом с хранилищем — он понадобится
  для доимпорта и отладки;
- `--dry-run` печатает всё то же, не создавая файлов.

Манифест Apple Notes — JSON-массив записей:

```json
{ "folder": "Дом/Стройка", "title": "Фундамент",
  "created": "2019-03-14T09:26:53Z", "modified": "2024-11-02T08:12:40Z" }
```

Формат производится будущим JXA-скриптом на маке; здесь он только потребляется.
Сопоставление: ключ «папка + заголовок»; неоднозначности и несопоставившееся —
в отчёт, **молчаливых пропусков нет**. Записи манифеста, не нашедшие файла, —
тоже в отчёт.

### `verify --root <dir>`
Полная проверка хранилища: валидность id-имён, разбор метаданных, `--check`
ядра на каждом файле (ноль дрейфа), ссылки `parent`, циклы, существование
локальных целей `![...]`-ссылок в `attachments/`, соответствие хеш-имён
содержимому, осиротевшие вложения (в отчёт, не удалять), отчёт.

### Безопасность миграции

Утилита **никогда не пишет в источник**. Импорт создаёт новое хранилище рядом;
старое дерево остаётся эталоном. Приёмка: `verify` зелёный, число заметок
сходится с числом исходных файлов + каталогов, выборочное сравнение
содержимого (`serialize(parse(источник))` == тело новой заметки без
метаданных).

## Инварианты и тесты

```
A. Метаданные: parse → serialize побайтово, включая неизвестные ключи
B. verify на свежемигрированном хранилище: ноль замечаний, ноль дрейфа
C. Загрузчик дерева не пишет в файлы ни при какой починке
```

Обязательные тесты:

- генератор id: длина, алфавит (нет `i l o u`), кодирование известного времени
  в известный префикс, `O_EXCL`-перегенерация при коллизии;
- метаданные: golden-файлы с известными/неизвестными ключами, кириллицей в
  тегах, отсутствующим блоком, комментарием без маркера `zametti` (остаётся
  блоком);
- `Divider` и image-спан: golden round-trip;
- импорт на синтетическом дереве-фикстуре: иерархия, времена из манифеста,
  переписанные и непереписанные ссылки, отчёт; вложения — две заметки с
  одинаковой картинкой (один файл в `attachments/`, две ссылки на него),
  битая `![...]`-ссылка (в отчёте, байты не тронуты);
- загрузчик: сирота, цикл, пустая заметка, заметка без заголовка;
- дерево: смена заголовка → подпись узла; перенос каталога → поддерево едет;
  запрет переноса в собственное поддерево;
- сортировка по `modified` со свежими сверху.

## Правила работы

- **Ничего за пределами репозитория и целевых каталогов утилиты не трогать.**
  `~/Documents/vpnotes` — только чтение, навсегда. Тесты — в каталоге сборки.
- Секция «Мои ошибки» в отчёте обязательна.
- Измерять, а не рассуждать; простое решение предпочтительнее общего.
- Сомнение — повод спросить, а не додумать.
