# Переносимая сборка под macOS

30.08.2026 (вторая редакция — универсальный бинарь, app и dmg; первая делала
только arm64). 04.09.2026 (третья редакция) — **по одному dmg на
архитектуру** вместо универсального бинаря (решение владельца: intel-маков
осталось немного, а универсальный бинарь носил каждому 30 МБ чужого кода),
стрип символов, версия из CMake. Задача владельца: самодостаточная программа
под обе архитектуры мака, завёрнутая в `Zametti.app` и `dmg`, как это уже
сделано под Linux одним файлом (`docs/zametti-portable-report.md`,
`docs/zametti-build-linux.md`).

## Что получается

`build-portable/` (пер-архитектурные cmake-деревья — в подпапках `arm64/` и
`x86_64/`, результат — в корне; раскладка — слово владельца):

| | |
|---|---|
| `<арх>/app/zametti` | бинарь половины, стрипованный |
| `<арх>/Zametti.app` | тот же бинарь + Info.plist (порождён CMake) + иконка, подпись ad-hoc |
| `Zametti-<версия>-arm.dmg` | app + симлинк Applications, UDZO |
| `Zametti-<версия>-intel.dmg` | то же для x86_64 (только по `intel` или `all`) |

Внутри бинаря — статический Qt 6.10.3 и всё вендоренное добро (libjxl,
libheif, libsodium, zstd, blake3, microtex…); снаружи только системные рамки
macOS, которые есть на любой машине по построению. TLS — SecureTransport,
OpenSSL не вшивается вовсе. Bundle id — `io.zametti.zametti`; версия — одна
на весь проект, из `project(zametti VERSION …)` корневого CMakeLists.txt
(`generated/version.txt` и `generated/Info.plist` пишет cmake при настройке).

**Пол системы — macOS 13.0 (Ventura).** Это минимум, который объявляет сам
Qt 6.10 (`qtbase/.cmake.conf`, `QT_SUPPORTED_MIN_MACOS_VERSION "13"`). Ниже Qt
собирается МОЛЧА — пол он не проверяет, только SDK и Xcode, — но работу на
живой macOS 12 никто не обещает и проверить её не на чем; обещать больше, чем
обещает Qt, нечестно. Развилка разобрана с владельцем 30.08.2026, решение — 13.0.

Версия Qt та же, что у линуксовой переносимой сборки, — 6.10.3 (решение
владельца): два разных Qt на двух системах означали бы два разных набора багов
вёрстки, а снимки приёмки сравнивают с одним и тем же.

## Оснастка — три скрипта, и это решение владельца

* `packaging/mac/zenv.sh` — общее окружение (`ZDEPS`, `ZBUILD`, пол, список
  архитектур `ZARCHS`, родная `ZHOSTARCH`); оба сборочных подключают его
  через `source`, поэтому Qt и программа собираются ОДНИМИ ключами.
* `packaging/mac/build-qt.sh` — весь статический Qt одним вызовом: заплаты из
  `patches/`, configure + сборка + установка qtbase, затем qtsvg — на каждую
  архитектуру из `$ZARCHS` в свой префикс `~/ai/work/zdeps/<арх>`.
* `packaging/mac/build-app.sh [arm|intel|all]` (умолчание `arm`) — программа
  от cmake до dmg, на каждую названную архитектуру по кругу: сборка, стрип,
  приёмка (пол, `otool -L`, дымовые запуски `--help`, `--version`,
  `--dump-config`), `<арх>/Zametti.app` с ad-hoc подписью, свой dmg. App
  остаётся рядом с dmg — упаковка занимает секунды, отдельный скрипт ей не
  нужен.

Устройство каталогов — слово владельца (30.08.2026): напрямую в `~/ai/work`
ничего не пишется; зависимости — `~/ai/work/zdeps` с подпапками по
архитектурам, их исходники и сборка — `zdeps/build`; эксперименты —
`~/ai/work/zametti-playground`; в репозитории `build/` — текущие
эксперименты, `build-portable/` — переносимая сборка.

Раздельных «настроить» и «собрать» больше нет: то была защита от ручного
`cmake --build . | tail`, где код возврата приходит от tail, — в скриптах с
`set -e -o pipefail` и без пайпов она не нужна.

## Рецепт по шагам

```bash
source packaging/mac/zenv.sh
mkdir -p "$ZBUILD"
for m in qtbase qtsvg; do
    git -C "$ZBUILD" clone --depth 1 --branch v6.10.3 "https://code.qt.io/qt/$m.git"
done

bash packaging/mac/build-qt.sh          # однажды; это часы — Qt строится дважды
bash packaging/mac/build-app.sh         # arm: Zametti-<версия>-arm.dmg
bash packaging/mac/build-app.sh intel   # x86_64: Zametti-<версия>-intel.dmg
bash packaging/mac/build-app.sh all     # оба dmg, по очереди
```

## Почему по dmg на архитектуру, а не универсальный бинарь

До 04.09.2026 половины склеивались `lipo -create` в универсальный бинарь
(73 МБ: arm64 34 + x86_64 39). Владелец снял это: intel-маков осталось
немного, а каждый пользователь носил 30 МБ кода не своей архитектуры. Теперь
у каждой архитектуры свой `.app` и свой `dmg`; `lipo` в скрипте нет вовсе.

Что осталось от прежней редакции — **одна архитектура на configure**.
Соблазн `CMAKE_OSX_ARCHITECTURES='arm64;x86_64'` ложный: libgav1, libsodium,
highway и libjxl выбирают SIMD ДО сборки по `CMAKE_SYSTEM_PROCESSOR`, у которой
одно значение на проход, — обе половины получили бы ARM-путь. Чем это
кончается, записано в `3rdparty/libgav1/CMakeLists.txt` рукой владельца: файл
без своего ключа «компилируется в ничто — молча, и библиотека просто
оказывается медленнее». Поэтому у каждой архитектуры свой configure и своя
сборка, по одной за раз.

## Кросс-половина x86_64 на Apple Silicon

* Для **Qt** чужая архитектура — кросс-сборка: configure требует
  `QT_HOST_PATH` — родной Qt, откуда берутся инструменты (moc, rcc).
  build-qt.sh отдаёт ему `~/ai/work/zdeps/arm64`; поэтому в `ZARCHS` родная
  архитектура идёт первой. Компилятор при этом остаётся родным — это сильно
  быстрее, чем гнать весь configure под Rosetta.
* Для **программы** одного `CMAKE_OSX_ARCHITECTURES` мало:
  `CMAKE_SYSTEM_PROCESSOR` остался бы `arm64`, и SIMD-выбор выше поехал бы.
  build-app.sh задаёт его явно — только процессор, БЕЗ `CMAKE_SYSTEM_NAME`
  (имя включило бы полный кросс-режим cmake), плюс тот же `QT_HOST_PATH`,
  который требует toolchain-файл кросс-собранного Qt.
* Проверка x86_64-половины — под Rosetta: `arch -x86_64 <бинарь>`; дымовые
  запуски в build-app.sh так и гоняются для обоих ломтей.

## Приёмка (встроена в build-app.sh)

На каждую половину: `strip` (размер до/после печатается) → `lipo -info` →
`otool -l` (`minos 13.0`) → `otool -L` (снаружи только `/usr/lib` и
`/System/Library`; отбираются строки с табуляцией) → дымовые запуски
`--help`, `--version` (обязан назвать ту же версию, что cmake) и
`--noconfig --dump-config`, x86_64 — под Rosetta → `codesign --verify --strict
--deep` → `hdiutil verify`. Сверх скрипта при сдаче 30.08 гонялся полный GUI
offscreen со свежим `--config-dir` на обоих ломтях: живёт, гаснет по SIGTERM
без падения.

## Находки

### Стрип: таблица символов — пятая часть бинаря

Нестрипованный arm64-ломоть: 35,3 МБ, из них `__TEXT` 27,4 МБ (код 20,7,
константы 5,7) и ~7 МБ таблицы символов (84 тысячи имён, `LC_SYMTAB`).
Стрип снимает именно её; код не трогается, приёмка (дымовые запуски) идёт по
уже стрипованному бинарю. То же сделано и линуксовой переносимой сборке
(`-s` в `packaging/linux/toolchains/linux-zsys.cmake`).

### Почему Linux-бинарь вдвое больше мак-ломтя

Вопрос владельца 04.09.2026: 35 МБ на маке против 60+ на Linux — не забыты
ли шрифты? Нет: двенадцать начертаний Plex и математические шрифты вшиты
одним `resources.qrc` на всех платформах (проверено по дереву ресурсов
мак-бинаря). Разница — в том, что Linux несёт внутри то, что мак берёт у
системы: статический OpenSSL 3.5 (на маке TLS — SecureTransport), xcb и
wayland со всеми помощниками и четыре платформы Qt против одной cocoa,
fontconfig/freetype; плюс таблицы символов ELF, которые до `-s` тоже не
стрипались. Замер по Linux (`size -A`, `strip` до/после) — за владельцем:
здесь линуксового бинаря нет.

### dmg без монтирования: makehybrid + convert

`hdiutil create -srcfolder` по дороге МОНТИРУЕТ образ в `/Volumes` — а
монтирование бывает запрещено (песочница агентов, CI): «create failed —
Operation not permitted». `hdiutil makehybrid -hfs` строит файловую систему
образа напрямую, `hdiutil convert -format UDZO` сжимает — оба шага без
монтирования, итог тот же.

### `__yield()` без объявления: Qt 6.10.3 не собирается новым AppleClang

`src/corelib/thread/qyieldcpu.h` зовёт `__yield()` под
`#if __has_builtin(__yield)` и не включает `<arm_acle.h>`. Прежние clang давали
его встроенным молча; **AppleClang 21 (Xcode 26)** считает `__yield`
БИБЛИОТЕЧНОЙ функцией: `__has_builtin` по-прежнему истина, но объявления в
области видимости нет, и вылезает `-Werror,-Wimplicit-function-declaration`.
Лечится включением `<arm_acle.h>`; заплата —
`packaging/mac/patches/qtbase-arm-yield-acle.patch`. Глушить предупреждение
нельзя: тогда вызов остался бы без объявления.
**Переносить при смене версии Qt** и проверять, не починено ли наверху.

### `<uchar.h>` в md4c

SDK Apple не поставляет `<uchar.h>` для C, а `md4c.h` включал его безусловно.
Починено в `3rdparty/md4c/md4c.h` по `__has_include` (не по `__APPLE__`:
вопрос в том, есть ли заголовок у инструментария, а имя платформы отвечает на
другой).

## Долги

* **Подписи Developer ID и нотаризации нет.** Ad-hoc подпись обязательна
  (без неё арм-маки не запускают вовсе), но Gatekeeper на чужом маке всё
  равно покажет предупреждение; `spctl --assess` отвечает `rejected` — для
  ad-hoc это норма, а снимают её только Developer ID + нотаризация.
* **dmg не открывался монтированием при сдаче** — песочница агента запрещает
  `/Volumes`; `hdiutil verify` пройден, содержимое собрано из проверенного
  `.app`, но щелчок по dmg руками остаётся за владельцем.
* Наборы на маке: четыре красных (`ExportPdf`, `FuzzOps`, `ImageRead`,
  `Zstd`) — они были красными и до переносимой сборки, разбор отдельной
  работой.
