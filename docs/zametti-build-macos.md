# Переносимая сборка под macOS

30.08.2026. Задача владельца: получить один самодостаточный файл, как это уже
сделано под Linux (`docs/zametti-portable-report.md`, `docs/zametti-build-linux.md`).

## Что получается

Один файл, `build-portable/app/zametti`. Внутри — статический Qt 6.10.3 и всё
вендоренное добро; снаружи остаются только системные рамки macOS, которые есть
на любой машине по построению и вкладывать которые нельзя и незачем.

| | |
|---|---|
| Qt | 6.10.3, статический, внутри |
| TLS | SecureTransport — системный; OpenSSL не нужен вовсе |
| FreeType, HarfBuzz | свои, внутри (не системные) |
| пол системы | macOS 12.0 (Monterey) — самая старая, что Qt 6.10 объявляет |
| архитектура | своя по умолчанию; универсальная — `ZARCHS='arm64;x86_64'` |

Версия Qt та же, что у линуксовой переносимой сборки, — решение владельца: два
разных Qt на двух системах означали бы два разных набора багов вёрстки, а
снимки приёмки сравнивают с одним и тем же.

## Чем мак отличается от линукса

**Sysroot не нужен.** На линуксе переносимость упирается в glibc, и её берут из
sysroot старой Ubuntu. На маке «пол» задаётся иначе — ключом
`-mmacosx-version-min` и версией SDK; совместимость назад система обеспечивает
сама.

**OpenSSL не нужен.** Qt берёт TLS у системы (SecureTransport), так что https
синхронизации работает без единой вшитой криптобиблиотеки. На линуксе OpenSSL
приходится вшивать.

**Одна платформа вместо трёх.** Ни xcb, ни wayland, ни их помощников: cocoa
одна, и она в Qt. Оттого и оснастки здесь втрое меньше.

## Оснастка

* `packaging/mac/zenv.sh` — общее окружение (`ZPREFIX`, `ZBUILD`, пол системы,
  архитектуры). Все чужие библиотеки и сама программа собираются ОДНИМИ
  ключами: разошедшиеся флаги у Qt и у программы — это бинарь, который
  собрался, но не запускается.
* `packaging/mac/qtbase-configure.sh` — настройка статического qtbase; она же
  накладывает заплаты из `packaging/mac/patches/`.
* `packaging/mac/build-qtsvg.sh` — qtsvg против собранного Qt.
* `packaging/mac/build-zametti.sh` — сама программа и проверка того, что чужого
  снаружи не осталось.

## Рецепт по шагам

```bash
source packaging/mac/zenv.sh
mkdir -p "$ZBUILD" && cd "$ZBUILD"
for m in qtbase qtsvg; do
    git clone --depth 1 --branch v6.10.3 "https://code.qt.io/qt/$m.git" "$m"
done
cd -

bash packaging/mac/qtbase-configure.sh
cd "$ZBUILD/qtbase-build" && cmake --build . -j8 && cmake --install .   # только -j8
cd -

bash packaging/mac/build-qtsvg.sh
bash packaging/mac/build-zametti.sh
```

Сборка Qt настраивается и собирается РАЗНЫМИ командами нарочно: код возврата
долгой сборки надо видеть отдельно — `cmake --build . | tail` отдаёт `$?` от
`tail`, и упавшая сборка отрапортует нулём (наступали на линуксе).

## Находки

### `__yield()` без объявления: Qt 6.10.3 не собирается новым AppleClang

`src/corelib/thread/qyieldcpu.h` зовёт `__yield()` под
`#if __has_builtin(__yield)` и не включает `<arm_acle.h>`. Прежние clang давали
его встроенным молча; **AppleClang 21 (Xcode 26)** считает `__yield`
БИБЛИОТЕЧНОЙ функцией: `__has_builtin` по-прежнему истина, но объявления в
области видимости нет, и вылезает `-Werror,-Wimplicit-function-declaration`.
Сборка падает на 186-м файле из 1865, ещё на bootstrap.

Лечится включением `<arm_acle.h>` — компилятор сам это и подсказывает в `note`.
Заплата: `packaging/mac/patches/qtbase-arm-yield-acle.patch`. Глушить
предупреждение нельзя: тогда вызов остался бы без объявления.

**Переносить при смене версии Qt** и проверять, не починено ли наверху.

### `<uchar.h>` в md4c

Отдельно от Qt, но из той же семьи: SDK Apple не поставляет `<uchar.h>` для C, а
`md4c.h` включал его безусловно — сборка падала на 11%. Починено в
`3rdparty/md4c/md4c.h` по `__has_include` (не по `__APPLE__`: вопрос в том, есть
ли заголовок у этого инструментария, а имя платформы отвечает на другой).

## Долги

* Универсальный бинарь (`arm64;x86_64`) оснасткой предусмотрен, но не собирался
  и не проверялся ни разу.
* Подписи и нотаризации нет. Без них чужой мак покажет предупреждение
  Gatekeeper.
* Наборы на маке: четыре красных (`ExportPdf`, `FuzzOps`, `ImageRead`, `Zstd`) —
  они были красными и до переносимой сборки, разбор отдельной работой.
