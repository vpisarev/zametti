# Zametti — бриф для Claude Code, этап 12: таблицы v1 — рендер и флип

## Контекст

Таблицы сегодня — verbatim-куски (rawSource, построчные QTextBlock), правятся
как текст. Этап делает им красивый показ, **не меняя ни байта хранения**:
рендер — чистое чтение. Правка остаётся текстовой (каретка внутри — исходник).

Это одновременно проба пера для формул (решение владельца): механизм
«рендер снаружи / исходник при каретке внутри», построенный здесь, формулы
унаследуют как готовый. Полноценная правка по ячейкам (вариант 2) — следующая
стадия, не этот этап.

Обязательное чтение: раздел «Картинки» отчёта 9 (резерв места и рисование по
геометрии), отчёт 10 («копия, а не слепок»), отчёт 5 (построчные блоки).

## Цель этапа

1. Красивый рендер GFM-таблиц: сетка, выравнивания, инлайн-разметка в ячейках.
2. Флип рендер ↔ исходник: триггер один — каретка/выделение внутри строк
   таблицы; двойной клик по сетке ставит каретку максимально близко к месту
   клика.
3. Вписывание широких таблиц: поля → усадка шрифта → (пол) перенос.
4. Инвариант этапа: **хранение не меняется ни байтом**.

## Не-цели

- правка по ячейкам, Tab между ячейками, добавление строк/колонок — вариант 2,
  отдельный этап; сериализация и канон пайпов там же (решение владельца уже
  записано: компактно, без пробельной набивки — здесь НЕ применяется, потому
  что здесь вообще ничего не пишется);
- `QTextTable` — отвергнут: чужая объектная модель (фреймы) против построчной
  нашей; весь проект рисует своё по геометрии — и таблицы тоже;
- формулы — следующие; этот этап лишь строит флип, который они возьмут;
- сортировка, поиск по таблице как по структуре, горизонтальный скролл
  (отвергнут владельцем в пользу усадки).

## Первая задача: замер и перепись

1. По корпусу владельца (копия, только чтение): сколько таблиц, распределение
   размеров (строки × колонки), максимальная ширина в символах. Эти числа —
   калибровка усадки и тестовых фикстур.
2. Время разбора + раскладки большой таблицы (50 строк × 8 колонок) — рендер
   не должен стать вторым «затыком прокрутки».

## Механизм флипа

- **Триггер один**: каретка или край выделения находится в строках таблицы →
  показывается исходник (обычные построчные блоки, как сегодня); иначе —
  рендер. Клавиатурный вход стрелками сверху/снизу флипает так же, как клик:
  правило про каретку, а не про жест;
- **рендер-состояние**: исходные блоки прячутся (`QTextBlock::setVisible(false)`
  — штатный механизм code folding), блок-хозяин несёт резерв высоты (машинерия
  картинок), сетка рисуется по геометрии в зарезервированном месте;
- **двойной клик по сетке** → каретка в ближайшую позицию исходника: строка по
  вертикали клика, ячейка по горизонтали, позиция в тексте ячейки по x внутри
  ячейки (карта «точка → ячейка → позиция» пишется сразу честной — это
  фундамент варианта 2). Одинарный клик по сетке пока не делает ничего
  (зарезервирован под выбор ячейки в варианте 2);
- выделение, протянутое «сквозь» таблицу извне, работает по исходным строкам
  (копирование отдаёт пайпы — честно); выделение внутри сетки в v1 не
  поддерживается;
- показ слепков истории рендерит таблицы так же (там каретки нет — всегда
  сетка); дифф-виды НЕ трогаются: они показывают строки, таблица в них —
  строки исходника, как и была.

## Разбор для показа

Отдельный прогон md4c с флагом таблиц **по куску таблицы, только ради
рендера** — хранение и штатный parse не меняются. Ячейки получают инлайн-спаны
(жир, курсив, код, ссылки) и рисуются существующей отрисовкой спанов.
Кривые таблицы рендерятся прощающе, как GitHub: лишние ячейки строки
отрезаются, недостающие — пустые; в исходнике при этом всё как написано.

## Сетка

- **ширины колонок — алгоритм авто-раскладки CSS2/HTML4** (RFC 1942, четверть
  века в каждом браузере): для колонки считаются min (самый длинный
  неразрывный токен по её ячейкам) и max (естественная ширина без переносов);
  Σmax ≤ W → всем max, переносов нет; Σmin ≤ W < Σmax → каждой min + доля
  остатка ∝ (max − min); Σmin > W → каскад широких таблиц (ниже). Переносится
  ровно та колонка, которой досталось меньше её max; колонки с min == max
  (числа, даты) не переносятся никогда;
- слова-монстры (URL, длинные идентификаторы): на полу каскада включается
  разрыв где угодно (аналог overflow-wrap: anywhere) — min схлопывается,
  вписывание гарантировано;
- выравнивание колонок из `:---:` / `---:` / `:---`;
- строка заголовка: полужирный + фон на полтона от палитры; тонкие линии
  сетки цветом рамок из палитры; внутриячеечные отступы — от кегля;
- перенос в ячейке — QTextLayout по назначенной ширине колонки (см. алгоритм
  выше);
- Ctrl+/Ctrl− масштабируют таблицу вместе с документом; HiDPI — физические
  пиксели, как везде.

## Широкие таблицы (правило владельца: «как картинки»)

Каскад включается, когда `Σmin > W` даже после раскладки (режим 3 алгоритма):

1. **расширение в поля**: таблице разрешено занять пустующие поля колонки
   текста — вплоть до ширины окна (W растёт);
2. всё ещё не влезает → **равномерная усадка шрифта таблицы**: min и max
   линейны по кеглю, целевой масштаб считается одним делением
   (`Σmin_нового = W`), без итераций;
3. **пол масштаба** (константа ~0.55) — ниже него усадка останавливается и
   включается разрыв-где-угодно в словах-монстрах (min схлопывается,
   вписывание гарантировано). Если пол сработал на реальном корпусе —
   строчка в отчёт: это сигнал владельцу, а не норма.

## Инварианты и тесты

```
A. Ни один .md не меняется: BLAKE3-хеши всех файлов хранилища до и после
   сессии рендера/флипов/кликов идентичны
B. Флип определяется только положением каретки/выделения; двойной клик и
   стрелки — два пути к одному правилу
C. Двойной клик попадает: строка, ячейка, позиция в тексте — по месту клика
D. Рендер не искажает содержимое: текст ячеек сетки == текст ячеек разбора
```

- флип: вход стрелками сверху/снизу, двойным кликом, выход кареткой наружу;
  Ctrl+Z после правки исходника — таблица остаётся исходником (каретка
  внутри), ушёл — отрендерилась;
- клик-карта: клетки по углам, середина, за пределами последней колонки
  (→ конец строки), по заголовку;
- ширины/выравнивания/инлайн-разметка — снимки Xvfb: обычная, широкая с
  усадкой, кривая (рваные строки), с жиром/кодом/ссылкой в ячейках, таблица
  в слепке истории;
- широкие: расширение в поля (окно шире колонки), усадка (узкое окно), пол
  и перенос (искусственно узко); широкое окно в матрице обязательно;
- пустые ячейки, таблица из одной строки, таблица в начале/конце документа;
- замер: разбор+раскладка 50×8 — мс в отчёт; прокрутка заметки с пятью
  таблицами — кадры не хуже обычного текста.

Критерий глазами: открыть заметки, которые «выглядели криво», — таблицы
читаются как таблицы; двойной клик в ячейку — каретка там, куда целился;
поправил пайп, увёл каретку — сетка вернулась; широкая таблица заняла поля и
ужалась, а не уехала за край.

## Правила работы

- Ничего за пределами репозитория; хранилище владельца — только чтение
  (корпусная статистика — по копии); тип сборки и файлы владельца оставлять
  как нашёл.
- Широкое окно в матрице UI-тестов; Debug и Release; снимки Xvfb как артефакт
  приёмки.
- Матрица «операция × край таблицы» пишется до починок (урок картиночных
  краёв этапа 9).
- Каждая починка проверяется снятием — целиком (урок этапа 10: снятие
  наполовину оставляет проверку зелёной).
- «Мои ошибки» обязательны. Измерять, а не рассуждать; сомнение — спросить.
